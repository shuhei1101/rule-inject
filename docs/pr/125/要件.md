# 要件

## 要望

rule-inject の dev-docs の配信元（`docs/`・`files.yaml`・`src/files.yaml`・`hooks/files.yaml`・`tests/files.yaml`・`skills/files.yaml`）の文書を、[A-5 の手順](https://github.com/shuhei1101/rule-inject/issues/99)で移行する。

| No | 工程 | 終わりの条件 |
| --- | --- | --- |
| 1 | 棚卸し | dev-docs の `search_docs` で、Mermaid・接頭辞の無いタグ・不足した description・本文に生の文字で記載した ID と Issue 番号とパス・避ける単語を含む文書を集め、移行する文書の一覧を作る |
| 2 | 文を表へ | 同じ属性を持つ項目が 2 件以上ある文・箇条書きが表になっている。`**キー**: 値` が 3 つ以上並ぶものは「項目 / 値」の表になっている |
| 3 | 文を削り、AI slop を修正する | 既出の言い直し・理由の説明・当たり前の注意が無い。残した文が規約『文章の書き方』の確認表と対応表に沿う |
| 4 | メタデータの付け直し | `files.yaml`・`files.yml` の全ての行のタグが `topic:`・`action:`・`tool:` の接頭辞を持つ。description（設計書は `lead`）が「何を定め、どんなときに参照するか」の 1 文で、description のチェックシートを満たす |
| 5 | エイリアスと用語 | 判定フローチャート『エイリアスの登録』『用語の登録』で登録すると判定した名前が `aliases` と用語集にある。用語集を配信する `alias_type` の行が `dev-docs.yaml` にある |
| 6 | 設計書とコードの関連 | `src/files.yaml`・`hooks/files.yaml`・`skills/files.yaml`・`tests/files.yaml` の行（テスト対象のコードを持たない `conftest.py` を除く）が、実在する設計書かコードの ID への `related`（`implements`・`tests`）を持ち、`trace_related` で辿れる |
| 7 | 本文に出さないものの移動 | 本文に検討事項の ID・Issue 番号・文書のパスが生の文字で無い（タイトル付きのリンクか関連のキーにある） |
| 8 | 検査 | `write_docs` の検査と mdmark の `check` を通り、画面で描いた図が重ならずに読める |

`docs/rules.yaml` が規約『markdown マーメイド』『判定フローチャート』の ID を指していないことを確かめる（develop では指していない）。

`未確定`: Mermaid の図を mdmark の map のマーカーで囲む工程（決める段: レビュー）
