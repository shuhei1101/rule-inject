# 要件

## 要望

ルール索引のエントリに、省略できる名前のキーを追加し、`rules.yaml` の全てのエントリに名前を記載する。
終了の条件は次のとおり。

- dev-docs のタブ「規約」のサイドバーで、`rules.yaml` の全てのエントリが、互いに異なり先頭の数文字で見分けられる名前で表示される
- 名前を持つ索引を、フックの読み取り・索引のチェック・書き込みの検査（`rule-inject-validate-entry`）が受け付ける
- 名前を持たない既存の索引は、今までどおり読める（破壊的変更にしない）
- `write_index_entry` で名前を書き込め、`list_rules` の応答で名前を受け取れる

`未確定`: 名前のキーの名前（決める段: データ設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `name` | project-index は `metadata` に書いていないキーを同じ名前の列から読むため、`project-index.yaml` の行を変えずに文書の名前になる | - |
| B | `title` | 他の設計書の `title` と同じ呼び名になる | `project-index.yaml` の行に `metadata: {name: title}` を追加する必要がある |

推奨: A

配信元の設定を変えずに済み、共通のメタデータのキー `name` と同じ意味で使用できるため。
