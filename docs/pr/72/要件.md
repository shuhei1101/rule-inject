# 要件

## 要望

リポジトリ直下に dev-docs の配信元の設定 `dev-docs.yaml` を新しく置き、判定フローチャートのページ [docs/使い方/ルールにするか文書にするかを決める.md](https://github.com/shuhei1101/rule-inject/blob/develop/docs/%E4%BD%BF%E3%81%84%E6%96%B9/%E3%83%AB%E3%83%BC%E3%83%AB%E3%81%AB%E3%81%99%E3%82%8B%E3%81%8B%E6%96%87%E6%9B%B8%E3%81%AB%E3%81%99%E3%82%8B%E3%81%8B%E3%82%92%E6%B1%BA%E3%82%81%E3%82%8B.md) を `documents[]` の行に載せてタグを付ける。

- `dev-docs.yaml` の書式は dev-docs の [設定](https://github.com/shuhei1101/dev-docs/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E8%A8%AD%E5%AE%9A.md) に従い、dev-docs のスキーマ（`src/dev_docs/schemas/dev-docs.schema.yaml`）に合うことを確かめる
- タグのマスターは置かない（`tags` のキーを持たない。D-169）
- ページは Markdown のまま、行の `metadata` か `defaults[]` でタグを持つ（dev-docs は front matter を読まない）
- このページは rule-inject では注入しない（[docs/rules.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/docs/rules.yaml) に登録しない。D-110）

`未確定`: ページに付けるタグ（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 他のリポジトリの `dev-docs.yaml` で使われている同じ意味のタグ（alias-inject の判定フローチャートの `scope:判定フローチャート` など）を使い回し、主題のタグを添える | D-169 のとおり、同じタグで他のリポジトリの判定フローチャートとまとめて引ける | 他のリポジトリの設定を確かめる手間が掛かる |
| B | rule-inject 固有のタグだけを付ける | 他のリポジトリを確かめずに付けられる | 他のリポジトリの判定フローチャートと同じタグで引けない |

推奨: A

D-110 で各リポジトリに判定フローチャートを置いており、同じタグで横断して引けるようにするため。
この端末では dev-docs が動いておらず `search_docs` の `group_by: tags` で引けないため、他のリポジトリの develop の `dev-docs.yaml` を読んで確かめる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 端末の設定（`~/.config/dev-docs/settings.yaml`）に rule-inject の配信元の行を追加し、`search_docs` でタグから引けることを確かめる | この端末には dev-docs の端末の設定が無く、dev-docs の導入と `/dev-docs:setup` での登録は #70 の「やること」が扱う。端末の設定はユーザーの環境で、`sources[]` の行と `scope` はユーザーの確認が要る | #70 |
| rule-inject のほかの文書（`docs/`・`dev/`）を `dev-docs.yaml` に載せる | Issue の範囲は判定フローチャートの 1 ページの配信だけ | #70 |
