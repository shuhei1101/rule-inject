# 要件

## 要望

索引の検査（`write_index_entry` と同じ検査）を、project-index の配信元の `validators[]` から呼べる CLI として出し、索引を文書として配信する行が指せるスキーマを出す。

- 配信元の `project-index.yaml` に索引を配信する行（`id: rule_index`・`paths: [rules.yaml]`・`records: rules`）と、この CLI を指す `validators[]` を記載すると、`write_docs`・画面のサーバーの書き込みの API が、検査に合格しない索引のエントリの書き込みを断る
- CLI は `validators[].run` の入出力に従う（標準入力にエントリ 1 件の YAML、標準出力に違反の JSON の配列。合格は空か `[]`）
- 違反の判定は `write_index_entry` の書き込みのチェックと同じ判定（スキーマの違反・ルールの場所の実在・フックが読み飛ばすエントリ）を使用し、判定を 2 か所に持たない
- `rule` の変数参照を CLI のプロセスの環境で展開できないエントリは違反にせず、ルールの場所の実在も確認しない（`validators[]` の実行環境に Claude Code のセッションの環境変数が届かないため）。URL の `rule` と解析できない正規表現は違反にする
- CLI はスキーマの検査も実行する。配信元の行の `schema` に索引のスキーマを指定すると、同じスキーマの違反が project-index の検査と CLI の両方から返却されるが、この重複は受け入れる
- `validators[].on` は既定の `[write]` で記載し、削除のときは検査を実行しない
- 索引を配信する行の `schema` が指せる場所に、索引のスキーマを配置する
- 索引を持つ配信元のリポジトリから CLI を起動する方法を、設計書と公開ドキュメントに記載する

他のリポジトリから CLI を起動する方法（インターフェース定義設計で決定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `pyproject.toml` の `[project.scripts]` にコマンドを登録し、`validators[].run` で `uvx --from git+https://github.com/shuhei1101/rule-inject@{タグ} {コマンド}` として起動する | 配信元ごとにタグでバージョンを固定でき、端末に rule-inject のクローンが無くても動く | 初回の起動で依存を取得するため、project-index の `script_timeout_sec`（既定 30 秒）を超えうる |
| B | 端末の rule-inject のクローン（MCP サーバーと同じ）の Python で `python -m` として起動する | 依存の取得が要らず速い | `validators[].run` にクローンの絶対パスを記載することになり、配信元のリポジトリに端末の場所が入る |
| C | `[project.scripts]` にコマンドを登録し、`global-setup` がクローンを `uv tool install --editable` で端末の PATH へ入れる。`validators[].run` はコマンド名だけを記載する | 依存の取得が要らず、絶対パスも記載しない。MCP サーバーと同じクローンのバージョンで判定する | `global-setup` に手順が 1 つ増え、導入していない端末では検査が実行できない |

採用: C

`validators[].run` は配信元のリポジトリに commit されるため、端末ごとに違う絶対パスを持たせられない。A は制限時間を超えると書き込みが断られる。

`未確定`: 索引のスキーマの置き場所（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の `src/rule_inject/features/index/check/index.schema.yaml` のまま、配信元の行の `schema` から `source: rule-inject`・`ref: {タグ}` で指す | 検査のコードとスキーマが 1 ファイルのまま | パスがパッケージの中の構成に依存する |
| B | `schemas/` へ移し、検査のコードもそこから読む | 公開するスキーマの置き場所がフォルダで分かる | パッケージ（wheel）に `schemas/` を含める設定が要る |

推奨: A

スキーマの原本を 1 か所に保ったまま、タグでバージョンを固定して指せる。
