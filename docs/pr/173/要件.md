# 要件

## 要望

knowledge のテンプレート『フォルダ構成』（`schemas/design/layout.schema.yaml`）の書式で、このリポジトリのフォルダ構成の設計書を `docs/layout/` に 1 枚作成する。

| 対象 | 内容 |
| --- | --- |
| 設計書 | `docs/layout/LAY-173-1.yaml`。リポジトリの直下からの全てのフォルダとファイルを入れ子の `entries[]` で記載する。生成物・一時ファイルは `gitignore[]`・`generated_from`、中身の種類は `content_types` で記載する。配下の配置を言語の規約が定めるフォルダ（`src/` など）は `children` を記載せず `convention` で規約を指す |
| 配信元の設定 | `project-index.yaml` の `documents[]` に layout の種類の行を追加し、`schema` は knowledge の `schemas/design/layout.schema.yaml` をリビジョンつきで指す（スキーマのコピーは `schemas/` に配置しない） |
| 目次 | `docs/layout/index.yaml` と、そこから生成する `docs/layout/README.md` を作成し、`docs/index.yaml`（生成する `docs/README.md`）に `layout/` の行を追加する |
| レビュー | 作成した設計書を規約『フォルダ構成の切り方とレビュー』（knowledge の `dev-folder-layout`）のレビューの観点で確認し、見つかった問題を問題ごとに Issue へ起票する。この作業 PR ではフォルダの移動・`.gitignore` の修正をしない |

終わりの条件:

- 設計書がスキーマの検査に通り、設計書の `entries[]` のパスがリポジトリの今のフォルダとファイルに一致する
- レビューの観点で見つかった問題が全て Issue になっている（見つからなければ、確認した観点を PR に記載する）

`未確定`: `project-index.yaml` で knowledge のスキーマを参照する記載方法（決める工程: ドキュメント修正）

今の `project-index.yaml` は全ての種類がリポジトリの `schemas/` のコピーを指している。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | layout の行だけ knowledge のスキーマをリビジョンつきで指す | コピーを増やさない（規約『ドキュメント管理』の `## YAML の設計書`） | 種類によって指し方が混ざる |
| B | layout も `schemas/` にコピーして指す | 今の指し方と統一できる | 規約『ドキュメント管理』に反し、コピーのずれが増える |

推奨: A

既存の種類のコピーから参照への切り替えは shuhei1101/ai-monitor#3188 の反映作業の範囲で、この作業 PR で増やすコピーをなくせば移行の対象が増えない。
