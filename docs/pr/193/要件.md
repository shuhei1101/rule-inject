# 要件

## 要望

AI Monitor の配布物の準拠バージョンを v0.4.0 から v0.5.0 へ上げ、追従 Issue の分類ごとに次を満たす。

| 分類 | 満たすこと |
| --- | --- |
| 準拠バージョン | [ai-monitor-version.ini](https://github.com/shuhei1101/rule-inject/blob/bf5327c/ai-monitor-version.ini) が `v0.5.0` を指す |
| サイトのレイアウト | `python -m ai_monitor.distribution import-site --version v0.5.0` で `docs/_theme/` を取り込み、控え [ai-monitor-theme.yaml](https://github.com/shuhei1101/rule-inject/blob/bf5327c/ai-monitor-theme.yaml) が v0.5.0 を指す |
| テンプレート・規約・判定・観点 | v0.4.0..v0.5.0 で変わったテンプレート・規約・判定フローチャート・チェックシート・観点を参照し直し、従っていない rule-inject の成果物（`docs/`・ルートの `README.md`・`CLAUDE.md`）を修正する |
| 配布先の反映作業 | [反映作業](./反映作業/index.yaml) を実行し、確認方法の値が rule-inject で観測できる。実行後に `docs/` の文書を mdmark check に渡して `map_unknown_class` が出るなら、`docs/mdmark.config.yaml` にも同じ `map.kinds` を記載する（端末の設定は `config.cascade: false` で、直下の設定は `docs/` の文書の check に読まれない） |

### 配布先の反映作業の dry-run の結果

| 作業 | dry-run | rule-inject の今の状態 |
| --- | --- | --- |
| 配布先の mdmark の設定へのノードの種類の記載 | changed | 直下に `mdmark.config.yaml` が無く、新しく作る |
