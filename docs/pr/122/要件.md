# 要件

## 要望

- `dev/` を廃止し、その下の文書を `docs/` の種類のフォルダと `schemas/` へ移す。移した後の `dev/` に追跡するファイルが 1 つも残らない
- 構成は [shuhei1101/ai-monitor#3307](https://github.com/shuhei1101/ai-monitor/pull/3307) の置き場所の規則（[docs/pr/3307/モニター.md](https://github.com/shuhei1101/ai-monitor/blob/1ac77c7c7961ca403a0b256dac8884ad0ce7b14b/docs/pr/3307/%E3%83%A2%E3%83%8B%E3%82%BF%E3%83%BC.md) の `### 種類のフォルダ` と `### 置き場所の規則`）に合わせる
  - `docs/` の第 1 階層は種類のフォルダと、`pr/`・`mock/`・`generated/`・`_` で始まる Pages の共通レイアウトだけにする
  - 種類のフォルダの中はフラットにし、YAML の設計書のファイル名を `{ID}.yaml`（言語の接尾辞を持つものは `{ID}.{lang}.yaml`）、Markdown のファイル名を今のファイル名（サブフォルダにあったものは `{サブフォルダ}-{ファイル名}`）にする
  - 公開ドキュメントの分類（はじめに / 使い方 / リファレンス）は `files.yml` の行の `category` で持つ。設計書の今のサブフォルダの分類（単一 / 複合ユースケース・MCP サーバー / プラグイン など）は持ち越さない（ai-monitor#3307 の設計書の Schema は `category` を持たない）
  - 目次の起点は `docs/index.yaml` の 1 つにし、行が種類のフォルダを指す
- 設計書を移す前に、AI Monitor の v0.4.0 の変換（[f135cff63](https://github.com/shuhei1101/ai-monitor/commit/f135cff63c1f6b4089f3db4bfdc1b2cb5bcdcb71) 以降の develop の `dev/テンプレート/変換/v0.4.0.py`）を `dev/` の置き場所のまま掛け、設計書の参照をパスから ID へ書き換える
- 各文書の公開範囲を `visibility`（`public` / `internal`）で持つ。今の `docs/` の下の文書は `public`、`dev/` から移した文書は `internal` にする。YAML の文書は各ファイルのキー、`docs/` の下の Markdown などは `files.yml` の行で持つ
- `docs/_config.yml` の `exclude` に、`internal` の文書だけを持つ種類のフォルダと `pr/`・`mock/`・`generated/` を記載する。`bundle exec jekyll build` の `_site/` に `internal` の文書が 1 つも無い
- 公開ドキュメント（はじめに・使い方・リファレンス）は `docs/guide/` 1 つにまとめ、上タブは分類から作る（表示名は今のまま）。Pages の URL は `docs/guide/` の下へ変わる
- 文書を指すパス（`*/files.yaml` の `related`・`dev-docs.yaml`・`rules.yaml`・`.gitignore`・`pyproject.toml`・`CLAUDE.md`）を移動先へ合わせる
- 移した後に次が通る
  - 設計書の検証（`python -m ai_monitor.design_docs validate --root {作業ツリーの直下}`）が、移す前からある誤り（#118 で削除した E2E のテストファイルを指す `test_file`）のほかに誤りを返却しない
  - `dev-docs.yaml` の `documents` の `paths` が、移した後の全ての設計書・目次を覆い、種類ごとの文書の数が移す前の develop と同じ
  - 単体・結合テストが全 pass し、lint が通る
