## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `flow` の図 | 各 ```` ```mermaid ```` のコードブロックを `<!-- map -->` と `<!-- /map -->` で囲む。コードブロックの中身は変えない | 補足 `<!-- map-data -->` は配置しない |
| 検査 | 書き換えた設計書を YAML として参照できることと、map の範囲の外の ```` ```mermaid ```` が残っていないことを確認する | `未確定`（決める段: ドキュメント修正）。設計書の検証のコマンドは `dev-docs.yaml` を参照するが、このリポジトリは `project-index.yaml` へ改名済みで、そのままでは実行できない |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設計書の検証のコマンドに `project-index.yaml` を `dev-docs.yaml` の名前で一時的に写した作業ツリーを渡して実行し、写したファイルは commit しない | Schema の検査と `mermaid.parse()` の検査を両方とも通せる | 一時ファイルの作成と削除の手間がかかる |
| B | YAML として参照できることと、map の範囲の外の ```` ```mermaid ```` の有無だけを grep で確認する | 手間が少ない | Schema と図の構文の検査を通さない |

推奨: A

コードブロックの中身を変えない書き換えでも、囲み方を誤ると Schema と図の構文の検査で落ちるため、検査を通して確認する。
