# 要件

## 要望

配信元 `rule-inject` の `project-index.yaml` に `nav` を記載し、dev-docs の画面のタブとサイドバーを knowledge の規約 `dev-docs-navigation` に合わせる。

- タブ（`tab-01`・`tab-02`）: 次の順の 7 件以下にする。配信元に無いタブは飛ばす。設計書の種類ごとのタブを作らず、タブ「設計書」にまとめる

  | 順 | タブ | 入れる文書（今の文書の行） |
  | --- | --- | --- |
  | 1 | はじめに | 公開ドキュメント（`docs/guide/files.yml`）の `category: はじめに` の文書（コアコンセプト・変更履歴） |
  | 2 | 使い方 | 公開ドキュメントの `category: 使用方法` の文書 |
  | 3 | 設計書 | アーキテクチャ図・非機能要件・シナリオ・インターフェース定義・モジュール構成・設定・ER図・データ・外部API・外部ライブラリ・テスト実行方法・フォルダ構成・開発コマンド・エージェント・MCP サーバー・起動の構成・エージェントフロー・LLM の呼び出し・精度評価・プロンプト |
  | 4 | 規約 | ルール索引のエントリ（`rules.yaml`） |
  | 5 | コード | ソースコード・フックの起動・テスト・スキル・リポジトリの直下のファイルの `files.yaml` の行 |
  | 6 | リファレンス | 公開ドキュメントの `category: リファレンス` の文書 |
  | 7 | 用語集 | 用語集（`docs/glossary/`） |

- サイドバー（`sidebar-01`・`sidebar-02`）: タブの中の文書を `group` か `auto.group_by` でまとめ、入れ子は 2 階層までにする。分けるかと分ける軸は判定フローチャート `flowchart-sidebar-group-split` で決める。グループの中は手順の順か重要さの順に並べ、名前の順は名前を知っている文書を探す一覧（用語集など）だけにする
- 目次（`index-01`）: フォルダの目次（`kind: index`）をタブとサイドバーに並べない。`auto` には `filter` に `not`（`kind` が `index`）を記載する
- 確認: 設定を修正した後に、dev-docs の画面（タブの並びと数・サイドバーのグループ・目次や内部のファイルが出ていないか・文書をスクロールした状態）をスクリーンショットで確認し、レビューで確認してから完了にする（shuhei1101/ai-monitor#3509）

規約のタブ「規約」には、ルール索引のエントリ（`rules.yaml`）を入れる。ルール索引のエントリは、このリポジトリで Claude Code に参照させる規約の一覧で、規約 `dev-docs-navigation` のタブ「規約」の「規約・テンプレート・判定フローチャート」に当たる。
