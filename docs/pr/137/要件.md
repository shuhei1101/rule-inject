## 要望

次の設計書の本文（lead 以外）に、[Issue #99](https://github.com/shuhei1101/rule-inject/issues/99) の手順 3・4・6 を適用する。

| フォルダ | 設計書 |
| --- | --- |
| `docs/architecture/` | ARCH-122-1 |
| `docs/nonfunctional/` | NFR-122-1 |
| `docs/config/` | CFG-122-1 |
| `docs/er/` | ER-122-1〜2 |
| `docs/external-api/` | API-122-1 |
| `docs/library/` | LIB-122-1〜6 |
| `docs/test-procedure/` | TP-122-1 |

| No | 工程 | 終わりの条件 |
| --- | --- | --- |
| 1 | 文を表へ | 同じ属性を持つ項目が 2 件以上ある文・箇条書きが表になっている。`**キー**: 値` が 3 つ以上並ぶものは「項目 / 値」の表になっている |
| 2 | 文を削り、AI slop を修正する | 既出の言い直し・理由の説明・当たり前の注意が無い。残した文が規約『文章の書き方』の確認表と対応表に沿う |
| 3 | 本文に出さないものの移動 | 検討事項の ID・Issue 番号・PR 番号・文書のパスが生の文字で無い（タイトル付きのリンクか関連のキーにある） |
| 4 | 検査 | 全ての対象の設計書が dev-docs の `write_docs` の検査を通る |

dev-docs の `write_docs` で記載し、設計書が定める値（制約の値・キー・スキーマ・実測値・コマンド）は変えない。

進行中の [Issue #124](https://github.com/shuhei1101/rule-inject/issues/124)（[PR #133](https://github.com/shuhei1101/rule-inject/pull/133)）が ER-122-1・LIB-122-1 を修正する場合は、先に develop へマージされた側の内容を取り込んでから、この 2 件を移行する。
