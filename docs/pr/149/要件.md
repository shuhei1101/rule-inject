# 要件

## 要望

MCP サーバーの instructions（MCP の `initialize` の応答の `instructions`）に、新しいファイルの作り方の決まりに続けて、rule-inject の MCP のツールの使い分けを記載する。

| 対象 | 要件 |
| --- | --- |
| いつこの MCP を探すか | 今効いているルールの確認・ファイルやツールの呼び出しにヒットするルールの検索・索引のチェックと編集・既読の記録の確認と削除・サーバーの状態の確認と再起動を、作業の言葉で 3〜5 個挙げる |
| grep・Read との使い分け | ルールの本文は案内された場所を Read で参照する。どのルールがヒットするかを調べるときは索引を grep せず `search_rules` を呼ぶ。MCP を探さない場面を、探す場面と同じくらいの数で挙げる |
| ツール間の順序 | 索引を編集した後に `check_indexes` で確認する、のように、順序に意味があるものだけを記載する |
| 記載の仕方 | 規約『注入文の書き分けと書き方』のとおり事実の文で記載し、ツールの description の繰り返しを含めない。4,096 字以内 |
| 新しいファイルの作り方の決まり | 今の文面を一字一句維持する |

規約『注入文の書き分けと書き方』は「最小の文から始め、使われていないと分かったら追加する」とも定めている。
[#133](https://github.com/shuhei1101/rule-inject/pull/133) では移す対象を新しいファイルの作り方の決まりに絞ったため使い分けを追加しなかった。
この PR では、同じ規約の「置き場所ごとに書くこと」の表が instructions に使い分けを記載すると定めていることから、追加する側で進める。
記載する場面と順序の文面は、インターフェース定義設計で確定する。
