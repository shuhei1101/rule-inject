# ルールのファイル自身を読む操作をそのルールの未読で止めず、search_rules をセッションの設定でフックと一致させる

## 概要

Claude Code が、自分自身に該当するルールのファイルを Read・読むコマンドで参照できるようになり、`search_rules` でフックと同じ判定を受け取れるようになる。

## 背景

[Issue #198](https://github.com/shuhei1101/rule-inject/issues/198) の報告。
索引のエントリの `paths` にルールのファイル自身が該当すると、ルール案内（PreToolUse）がそのルールを未読として止め、既読の記録は参照した後（PostToolUse）に付くため、再試行しても参照できない（実例: [shuhei1101/aituber#167](https://github.com/shuhei1101/aituber/pull/167)）。
あわせて、MCP の `search_rules` は常駐のサーバーのプロセスの環境変数で設定ファイルを決めるため、セッションの `RULE_INJECT_CONFIG` にだけあるプロジェクトの索引を照合せず、フックの判定と食い違う。
