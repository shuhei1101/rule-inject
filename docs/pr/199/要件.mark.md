# 要件

## 要望

| 項目 | 完了の条件 |
| --- | --- |
| ルール自身の参照 | 索引のエントリの `paths` にルールのファイル自身が該当するとき、そのファイルを参照する操作（Read・Grep・Bash の読み取りのコマンド）を、そのルールが未読でも止めない。ほかに該当する未読のルールがあれば、そのルールでは今までどおり止める |
| 検索の設定 | `search_rules` が、呼んだセッションの `RULE_INJECT_CONFIG` が指す設定ファイル（無ければ既定の場所）で照合し、同じ対象・同じ操作でのルール案内の判定と同じルール・同じ止めるかを返却する。返却する `config_path` はその設定ファイルの場所 |
| 同じ型の箇所 | 設定ファイルを同じ解決（`_project_settings`）で取得する `list_rules`・`check_indexes`・`write_index_entry`・`delete_index_entry` も、呼んだセッションの設定の索引を対象にする |

`未確定`: 呼んだセッションの設定ファイルの場所をサーバーへ指定する方法（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ツールに設定ファイルの場所の引数を追加し、PreToolUse のフックがセッションの `RULE_INJECT_CONFIG` をその引数へ入れる | Claude Code が引数を指定しなくても一致する | フックが MCP のツールの引数を書き換える処理が増える |
| B | ツールに設定ファイルの場所の引数を追加し、Claude Code が指定する | フックを変えない | 指定し忘れると今までどおり食い違う |

推奨: A

指定し忘れても食い違わないことが完了の条件で、利用者や Claude Code に手順を追加せずに済むため。
