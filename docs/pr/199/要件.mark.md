# 要件

## 要望

| 項目 | 完了の条件 |
| --- | --- |
| ルール自身の参照 | 参照する操作（Read・Grep・Bash の読み取りのコマンド）の対象が、読み込んだ索引のどれかのエントリのルールの場所であれば、その操作を止めない。対象自身のルールは案内せず、ほかに該当する未読のルールは止めずに案内する（2 つのルールが互いのファイルに該当しても、どちらも参照できる） |
| 検索の設定 | `search_rules` が、呼んだセッションの `RULE_INJECT_CONFIG` が指す設定ファイル（無ければ既定の場所）で照合し、同じ対象・同じ操作でのルール案内の判定と同じルール・同じ止めるかを返却する。返却する `config_path` はその設定ファイルの場所 |
| 同じ型の箇所 | 設定ファイルを同じ解決（`_project_settings`）で取得する `list_rules`・`check_indexes`・`write_index_entry`・`delete_index_entry` も、呼んだセッションの設定の索引を対象にする。既読の記録の場所を設定から取得する `get_read_records`・`delete_read_records` も、呼んだセッションの設定の記録の場所を対象にする |

## 決定事項

| 論点 | 決定 | 決めた工程 |
| --- | --- | --- |
| 呼んだセッションの設定ファイルの場所をサーバーへ指定する方法 | ツールに引数 `config_path` を追加し、PreToolUse のフック（インターフェース定義『ツールの引数への設定の記入』）がセッションの `RULE_INJECT_CONFIG` をその引数へ入れる（案 A） | インターフェース定義設計 |
