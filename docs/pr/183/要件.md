# 要件

## 要望

knowledge のテンプレート『開発コマンド』（`schemas/design/dev_command.schema.yaml`）の書式で、このリポジトリの開発コマンドの設計書を `docs/dev-command/` に 1 枚作成し、フォルダ構成の設計書 `docs/layout/LAY-173-1.yaml` の生成物・コピーのエントリに `generated_from` を記載する。

| 対象 | 内容 |
| --- | --- |
| 開発コマンドの設計書 | `docs/dev-command/CMD-183-1.yaml`。テンプレートのとおり全ての分類を作り、`ビルド・生成` の分類に、`index.yaml` から `README.md` を生成するコマンド（AI Monitor の `python -m ai_monitor.design_docs publish`）・`docs/_theme/` を AI Monitor からコピーするコマンド（`python -m ai_monitor.distribution import-site`）・`docs/generated/` を生成するコマンド（`python -m ai_monitor.design_docs generate`）を記載する。テストと静的検査の分類は `refs` でテスト実行方法 `TP-122-1` を指す。記載したコマンドは実行して確認し、確認した記録を `verification` に残す |
| 配信元の設定 | `project-index.yaml` の `documents[]` に dev_command の種類の行を追加し、`schema` は knowledge の `schemas/design/dev_command.schema.yaml` を他の種類と同じリビジョンで指す |
| フォルダ構成の設計書 | 生成物・コピーのエントリ（`docs/` の `README.md`・種類のフォルダの `README.md`・`docs/_theme`・`docs/generated`）に、生成元のパスと開発コマンドの分類への参照（`CMD-183-1#categories[ビルド・生成]`）を持つ `generated_from` を記載する。`docs/` の配下に `dev-command` のフォルダのエントリを追加する |
| 目次 | `docs/dev-command/index.yaml` と、そこから生成する `docs/dev-command/README.md` を作成し、`docs/index.yaml`（生成する `docs/README.md`）に `dev-command/` の行を追加する。`docs/_config.yml` の `exclude` に `dev-command/` を追加する |

終わりの条件:

- 開発コマンドの設計書とフォルダ構成の設計書が knowledge のスキーマの検査に通る
- フォルダ構成の設計書の生成物・コピーのエントリが全て `generated_from` を持ち、`command` が開発コマンドの設計書の分類を指す

`未確定`: 種類のフォルダの `README.md` に `generated_from` を記載する方法（決める工程: ドキュメント修正）

今の設計書は `docs/` の直下の `README.md` だけをファイルのエントリに持ち、種類のフォルダの `README.md` は `naming` のパターンにしか無い。
`generated_from` はエントリにしか記載できない。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 種類のフォルダごとに `README.md` のファイルのエントリを追加して `generated_from` を記載し、`naming` から `README.md` を除外する | 全ての生成物の生成元を設計書から参照できる | エントリが種類のフォルダの数だけ増える |
| B | `docs/` の直下の `README.md` のエントリにだけ記載し、種類のフォルダの `README.md` は `naming` のまま残す | 設計書の行が増えない | 種類のフォルダの `README.md` の生成元を設計書から参照できず、テンプレートの決まり「生成物・複製のエントリには `generated_from` を記載する」を満たさない |

推奨: A

テンプレートの決まりを満たすのは A だけのため。
