# 設定ファイル

設定ファイルのキーと、`global`・`projects` の当て方と重ね方

利用者ごとの設定は、環境変数 `RULE_INJECT_CONFIG` が指す YAML の設定ファイルで受け取る（[環境変数](./環境変数.md)）。
置き場所は `~/.config/rule-inject/settings.yaml`。
必要なキーの一覧は、プラグインの直下の [settings.sample.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/settings.sample.yaml)。

設定ファイルの中身は、フックが呼ばれるたびに読み直すので、変えた内容は次の呼び出しから効く。
`RULE_INJECT_CONFIG` が無いときは、設定ファイルを読まず、全てのキーを既定値で動かす。

最上位に `global` と `projects` を置く。

```yaml
global:
  indexes:
    - ~/rules/index.yaml
projects:
  - match: my-project
    indexes:
      - rules/project.yaml
```

## global

どのプロジェクトで起動しても効く値。

<!-- table: data -->

| キー | 型 | 内容 | 既定値 |
| --- | --- | --- | --- |
| `indexes` | 文字列のリスト | どのプロジェクトでも読む索引のパスの並び。絶対パスか `~` で始まるパス | `${XDG_CONFIG_HOME:-~/.config}/rule-inject/rules.yaml` |
| `state_dir` | 文字列 | セッションごとの既読の記録ファイル・案内済みの記録ファイル・既読の履歴ファイルを置くフォルダ。絶対パスか `~` で始まるパス | `${XDG_STATE_HOME:-~/.local/state}/rule-inject` |
| `log_dir` | 文字列 | 失敗した操作を書くログのフォルダ。絶対パスか `~` で始まるパス | `${XDG_STATE_HOME:-~/.local/state}/rule-inject/logs` |
| `record_retention_days` | 整数 | 既読の記録ファイル・案内済みの記録ファイル・既読の履歴ファイルを残す日数。1 以上 | `30` |
| `log_retention_days` | 整数 | ログのファイルを残す日数。1 以上 | `3` |
| `server_port` | 整数 | 常駐の MCP サーバーが `127.0.0.1` で待ち受けるポート。1024〜65535。環境変数 `RULE_INJECT_PORT` で上書きできる（[環境変数](./環境変数.md)） | `8783` |
| `dev_docs_url` | 文字列 | `check_indexes` が使われているタグを引く dev-docs の MCP サーバーの URL。`http://` か `https://` で始まる | `http://127.0.0.1:8781/mcp` |

<!-- /table -->

記録とログのフォルダは全てのプロジェクトで共通のため、`state_dir`・`log_dir` と保持日数は `projects` に置けない。
サーバーは全てのプロジェクトで 1 つのため、`server_port`・`dev_docs_url` も `projects` に置けない。
`server_port` はフックが使わず、サーバーが起動時に 1 回だけ読む。変えたときはサーバーを再起動する（[MCPサーバー](../はじめに/コアコンセプト/MCPサーバー.md)）。
`dev_docs_url` もフックが使わず、`check_indexes` が呼ばれるたびに読むので、変えた内容は次の呼び出しから効く。

## projects

要素ごとに `match` と、そのプロジェクトで効く値を持つ並び。

| キー | 型 | 内容 | 既定値 |
| --- | --- | --- | --- |
| `match` | 文字列 | その要素を当てるプロジェクト。絶対パスかプロジェクト名。必須 | なし |
| `indexes` | 文字列のリスト | 当たったプロジェクトだけで読む索引のパスの並び。絶対パス・`~` で始まるパス・プロジェクトの直下（環境変数 `CLAUDE_PROJECT_DIR`）からの相対パス | `${CLAUDE_PROJECT_DIR}/rules.yaml` |

要素が持てるキーは `match` と `indexes` だけで、ほかのキーは設定ファイルの誤りになる。

### 当て方

`match` は、起動したプロジェクトの直下（`CLAUDE_PROJECT_DIR`）に次のとおり当たる。

| `match` | 当たる条件 |
| --- | --- |
| 絶対パス | `CLAUDE_PROJECT_DIR` がそのパスか、その配下のとき |
| プロジェクト名 | リポジトリのフォルダ名が一致したとき |

`.claude/worktrees/` の下の worktree は、本体のパスとフォルダ名で見る。

### 重ね方

当たった要素の `indexes` を、並びの順に `global.indexes` の後ろへ追加する。
全てのエントリを合わせて当てる。

### 既定の置き場所

`indexes` を書かないときは、既定の置き場所の索引を読む。
既定の置き場所にファイルが無いとき（プロジェクトの索引は `CLAUDE_PROJECT_DIR` が無いときも）は、何も知らせずに読まない。
`global.indexes` を空の並び `[]` にすると、ユーザーの既定の置き場所も読まない。
当たった要素のどれかが `indexes` を持つときは、空の並び `[]` でも、プロジェクトの既定の置き場所を読まない。

### 相対パス

`projects` の `indexes` の相対パスは、`CLAUDE_PROJECT_DIR` から解く。
Claude が `cd` した先へ動く作業フォルダは基準に使わない。
`global.indexes` の相対パスは設定ファイルの誤りになる。

索引の中身は [索引の書式](./索引の書式.md)。

## 既読の記録の置き場所

`state_dir` には、絶対パスか `~` で始まるパスを記載する。
フォルダが無ければ書く側が作る。
記録ファイルは `{state_dir}/{session_id}.txt` で、1 行に 1 つのルールの場所を持つ。
最後に追記してから 30 日を過ぎた記録ファイルは、セッションの開始時に削除される（[ルールの案内](../はじめに/コアコンセプト/ルールの案内.md)）。
日数は `record_retention_days` で変えられる。

同じフォルダの `{session_id}.guided.txt` には、止めずに案内したルールの場所を 1 行ずつ持つ。
既読の記録と同じく、圧縮の前とセッションの開始時の掃除で削除される。

同じフォルダの `{session_id}.history.jsonl` には、既読にした履歴を 1 行ずつ持つ（[ルールの案内](../はじめに/コアコンセプト/ルールの案内.md)）。
圧縮の前には削除されず、最後に追記してから `record_retention_days` 日を過ぎたものが、セッションの開始時の掃除で削除される。

## ログの置き場所

`log_dir` には、絶対パスか `~` で始まるパスを記載する。
フックは、失敗した操作をこのフォルダの `{yyyymmdd}_rule-inject.log`（日付は UTC）へ 1 行ずつ書く。
日付が今日から `log_retention_days` 日以上前のファイルは、セッションの開始時に削除される。

## 設定ファイルの誤り

`RULE_INJECT_CONFIG` が指すファイルが次のいずれかのとき、設定ファイルの誤りとして扱う。

- ファイルが無い・読めない
- YAML として読めない・UTF-8 として読めない
- 知らないキーや、キーの表の値の範囲の外の値を持つ
- `match` を持たない `projects` の要素がある

誤りのとき、設定ファイルを使わず、既定値でも動かさない。
索引は読まず、掃除は何も削除しない。
ルールを案内するフックは、操作を止めずに、設定ファイルの場所と理由をコンテキストへ載せる。
各フックは、失敗した操作 `read_settings` を既定のログのフォルダ（`${XDG_STATE_HOME:-~/.local/state}/rule-inject/logs`）へ追記する。
常駐の MCP サーバーは、起動のときは待ち受けずに標準エラーへ場所と理由を書いて 0 以外の終了コードで終わり、ツールの呼び出しのときは `isError: true` で場所と理由を返す。
