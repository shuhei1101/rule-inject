# セットアップ

プラグインを読み込み、索引を指す環境変数を置くまでの手順

## 前提条件

| 項目 | 内容 |
| --- | --- |
| OS | Linux か WSL（macOS と、WSL を使わない Windows は対象外） |
| `python3` | 3.12 以上。フックが端末の `python3` で動く |
| uv | MCP サーバーの起動に使う |

> [!WARNING]
> `python3` が 3.12 より古いと、フックは動かず、「フックには Python 3.12 以上が要ること」と動いた版がコンテキストに載る。

## 手順

### 1. プラグインを読み込む

Claude Code で、このリポジトリを marketplace として足し、プラグインを入れる。

```text
/plugin marketplace add shuhei1101/rule-inject
/plugin install rule-inject@rule-inject
```

一度入れれば、起動のたびに指定しなくてよい。
新しい版は `/plugin marketplace update rule-inject` で取り込む。

プラグインはフック 5 つ（`PreToolUse` 2 つ・`PostToolUse`・`PreCompact`・`SessionStart`）と、MCP サーバー `rule-inject` を持つ。
MCP サーバーは `.mcp.json` の `uv run` で起動し、常駐するサーバーは持たない。

### 2. ルールの索引を書く

ルールの場所と、それを当てるパスの対応を YAML に書く。
書式は [索引の書式](../リファレンス/索引の書式.md)。

```yaml
rules:
  - rule: ./python.md
    paths:
      - "**/*.py"
    on: [write]
```

### 3. 索引を環境変数で指す

Claude Code の設定の `env` に、索引のパスを置く。

| 索引の用途 | 置く設定 | 環境変数 |
| --- | --- | --- |
| 全プロジェクトで使う | `~/.claude/settings.json` | `RULE_INJECT_INDEXES_USER` |
| そのプロジェクトだけで使う | プロジェクトの `.claude/settings.json` | `RULE_INJECT_INDEXES_PROJECT` |

```json
{
  "env": {
    "RULE_INJECT_INDEXES_USER": "~/rules/index.yaml"
  }
}
```

どちらもカンマ区切りで複数の索引を並べられる。
置いた後と変えた後は、Claude Code を起動し直す。
一覧は [環境変数](../リファレンス/環境変数.md)。

## 確かめる

索引の `paths` に当たるファイルを Claude Code に書かせる。
1 回目は操作が止まり、ルールの場所が案内される。
本文を取得してからやり直すと、同じ操作が通る。
仕組みは [ルールの案内](../はじめに/コアコンセプト/ルールの案内.md)。

## 外すとき

設定の `env` から `RULE_INJECT_INDEXES_USER` と `RULE_INJECT_INDEXES_PROJECT` を消すと、案内は出なくなる。
