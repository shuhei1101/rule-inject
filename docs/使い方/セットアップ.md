# セットアップ

プラグインを読み込み、設定ファイルを置いて環境変数で指すまでの手順

## 前提条件

| 項目 | 内容 |
| --- | --- |
| OS | Linux か WSL（macOS と、WSL を使わない Windows は対象外） |
| `python3` | 3.12 以上。フックが端末の `python3` で動く |

> [!WARNING]
> `python3` が 3.12 より古いと、フックは動かず、「フックには Python 3.12 以上が要ること」と動いたバージョンがコンテキストに載る。

## 手順

### 1. プラグインを読み込む

Claude Code で、このリポジトリを marketplace として追加し、プラグインを入れる。

```text
/plugin marketplace add shuhei1101/rule-inject
/plugin install rule-inject@rule-inject
```

一度入れれば、起動のたびに指定しなくてよい。
新しいバージョンは `/plugin marketplace update rule-inject` で取り込む。

プラグインはフック 6 つ（`PreToolUse`・`PostToolUse` 2 つ・`PreCompact`・`SessionStart` 2 つ）を持つ。

### 2. ルールの索引を書く

ルールの場所と、それを当てるパスの対応を YAML に書く。
書式は [索引の書式](../リファレンス/索引の書式.md)。

```yaml
rules:
  - rule: ./python.md
    paths:
      - "**/*.py"
    on: [write]
```

### 3. 索引を設定ファイルで指す

設定ファイル `~/.config/rule-inject/settings.yaml` に、索引のパスを記載する。
キーの一覧は、プラグインの直下の [settings.sample.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/settings.sample.yaml)。

| 索引の用途 | 記載するキー |
| --- | --- |
| 全プロジェクトで使う | `global.indexes` |
| そのプロジェクトだけで使う | `projects` の要素の `indexes`（`match` でプロジェクトを指す） |

```yaml
global:
  indexes:
    - ~/rules/index.yaml
projects:
  - match: my-project
    indexes:
      - rules/project.yaml
```

どちらも複数の索引を並べられる。
`projects` の要素の書き方と当て方は [設定ファイル](../リファレンス/設定ファイル.md)。

続けて、`~/.claude/settings.json` の `env` に、設定ファイルのパスを置く。

```json
{
  "env": {
    "RULE_INJECT_CONFIG": "~/.config/rule-inject/settings.yaml"
  }
}
```

プロジェクトの `.claude/settings.json` の `env` には置かない。
置いた後と変えた後は、Claude Code を起動し直す。
一覧は [環境変数](../リファレンス/環境変数.md)。

索引を既定の置き場所に置くときは、設定ファイルも環境変数も書かなくてよい。

| 索引の用途 | 既定の置き場所 |
| --- | --- |
| 全プロジェクトで使う | `${XDG_CONFIG_HOME:-~/.config}/rule-inject/rules.yaml` |
| そのプロジェクトだけで使う | プロジェクトの直下の `rules.yaml` |

### 4. ログと既読の記録の残し方を変える（任意）

既定のままでよければ飛ばす。
変えるときは、設定ファイルの `global` に記載する。

| 変えたいこと | キー | 既定値 |
| --- | --- | --- |
| ログを出すフォルダ | `global.log_dir` | `${XDG_STATE_HOME:-~/.local/state}/rule-inject/logs` |
| ログのファイルを残す日数 | `global.log_retention_days` | `3` |
| 既読の記録ファイルと既読の履歴ファイルを残す日数 | `global.record_retention_days` | `30` |

```yaml
global:
  log_dir: ~/logs/rule-inject
  log_retention_days: 7
```

設定ファイルを変えた内容は、次のフックの呼び出しから効く。

### 5. MCP サーバーを常駐させる（任意）

効いているルールの確認・ルールの検索・索引のチェックと編集をツールで行うときに使う。
フックはサーバーに依存しないため、サーバーを立てなくても案内は動く。
役割は [MCPサーバー](../はじめに/コアコンセプト/MCPサーバー.md)、ツールは [MCPツール](../リファレンス/MCPツール.md)。

ローカルのクローンで、サーバーの依存を入れて前面で起動する。

```bash
cd ~/repo/rule-inject
RULE_INJECT_CONFIG=~/.config/rule-inject/settings.yaml uv run --extra server python -m rule_inject.server
```

- 待ち受けるのは `127.0.0.1` の `global.server_port`（既定 `8783`）。その起動だけ変えるときは環境変数 `RULE_INJECT_PORT` を渡す
- `RULE_INJECT_CONFIG` はフックと同じ設定ファイルを指す。`rule` の `!{名前}` を使う索引は、同じ名前の環境変数も起動する側に置く（[環境変数](../リファレンス/環境変数.md)）
- ポートが使われているときと、設定ファイルが読めないときは、待ち受けずに標準エラーへ理由を書き、0 以外の終了コードで終わる
- 止めるときは Ctrl+C か SIGTERM。SIGTERM の終了コードは 143

常駐させるときは、systemd のユーザーのユニットなどで起動する。
次は `~/.config/systemd/user/rule-inject.service` の例。

```ini
[Unit]
Description=rule-inject MCP server

[Service]
WorkingDirectory=%h/repo/rule-inject
Environment=RULE_INJECT_CONFIG=%h/.config/rule-inject/settings.yaml
ExecStart=%h/.local/bin/uv run --extra server python -m rule_inject.server
Restart=on-failure
SuccessExitStatus=143

[Install]
WantedBy=default.target
```

`SuccessExitStatus=143` は、SIGTERM で止めた終了を失敗として扱わないための指定。

```bash
systemctl --user daemon-reload
systemctl --user enable --now rule-inject.service
```

Claude Code には、HTTP の MCP サーバーとして登録する。
ポートは、サーバーが待ち受けるポートと同じ値にする。

```bash
claude mcp add --transport http -s user rule-inject http://127.0.0.1:8783/mcp
```

`global.server_port` と `RULE_INJECT_PORT` は、サーバーの起動時に 1 回だけ読む。
変えたときは、サーバーを再起動し、登録した URL のポートも合わせる。

## 確かめる

索引の `paths` に当たるファイルを Claude Code に書かせる。
1 回目は操作が止まり、ルールの場所が案内される。
案内された場所を Read で読んでからやり直すと、同じ操作が通る。
仕組みは [ルールの案内](../はじめに/コアコンセプト/ルールの案内.md)。

## 外すとき

設定ファイルの `global.indexes` を空の並び `[]` にし、使うプロジェクトごとに `projects` の要素の `indexes` も `[]` にすると、案内は出なくなる。
`indexes` を削除するだけでは、既定の置き場所に索引があればその索引で案内が出る。
