# ルールの案内

未読のルールの案内・既読の記録・既読の履歴・圧縮での破棄の仕組み

Claude Code がファイルを触る前に、そのファイルにヒットする未読のルールをコンテキストへ案内する。
ルールは同梱せず、利用者が記載した索引（[索引の書式](索引の書式.md)）に記載したものだけが対象になる。

## 案内

`PreToolUse` フックが、ツールを呼ぶ直前に、操作の対象のパスかツール名を索引と照らす。
ヒットするルールのうち、そのセッションで未読のものを案内する。

MCP のツールは、ツール名に加えて引数のキーと値でも適用される（索引の `args`）。
dev-docs の `search_docs` の `filter` のような条件の木の引数は、`filter[tags]` のキーで、入れ子の `and`・`or` の中のタグ・文書の種類の値にも適用される（`not` の中と否定の条件は適用しない）。
パスとツール名と引数のパターンには、glob のほかに `re:` で始まる正規表現も記載できる（[索引の書式](索引の書式.md)）。

| 操作の種別 | 対象のツール |
| --- | --- |
| `read` | Read、ファイルを指す Grep、Bash の読むコマンド（`cat` `head` `tail` `less` `more` `grep` `rg` `sed` `awk` `wc` `bat`） |
| `write` | Edit、Write、NotebookEdit |
| `mcp` | MCP のツール |

Bash の読むコマンドの引数のうち、引用符の外の glob（`src/*.py`）は展開し、ヒットしたファイルを読む対象にする。
`for f in {単語の並び}; do cat "$f"; done` のように、`do` の中の読むコマンドが `for` の変数を引数に取るときは、単語の並びを読む対象にする。

- 操作の種別がエントリの `on` にヒットするときは、操作を止めて、ルールのパスと参照の方法を案内する。本文を参照した後に、同じ操作を再試行する
- `on` にヒットしないときは、止めずに案内する。案内には「再試行」を含めない
- 止めない案内は、ルールごとにセッションで 1 回だけ出す。案内した場所はセッションごとの案内済みの記録（`{session_id}.guided.txt`）に追記する
- 同じルールに複数のエントリがヒットしても、案内と止めるかの判定はルールごとに 1 つにまとめる
- 案内が 10,000 字を超えるときは、止めるルールを先に並べて収まる分だけ記載し、記載しきれなかった件数を末尾に添える。残りは未読のままなので、再試行したときに案内される
- 索引で `enabled: false` にしたエントリは、案内にも既読の記録にも使用しない。同じルールの場所を指す有効なエントリが別にあれば、そのエントリで案内する（[索引の書式](索引の書式.md)）

新しいファイルは、空で作ってから中身を記載する。
空で作った時点でヒットするルールが案内されるため、本文を読んでから記載できる。
MCP サーバーが、この決まりを接続時の instructions でセッションとサブエージェントへ届ける（[MCPサーバー](コアコンセプト-MCPサーバー.md)）。

## 検索結果への案内

Grep・Glob・検索の Bash（`grep` `rg` `find` `ls`）を呼んだ直後に、`PostToolUse` フックが結果に出た実在するファイルを索引と照らす。
ヒットするルールのうち、そのセッションで未読で、まだ案内していないものを、読むかは任意と伝えて止めずに案内する。
照合するのは結果の先頭から 100 件までで、超えた分の件数は案内に添える。

## 本文の取得

案内に載ったルールは、Read で参照して本文を受け取る。
索引のエントリに `read_tool` を記載したルールは、パスの行の下に `ツール:` の行が載り、そのツールで必要な部分だけを参照できる（[索引の書式](索引の書式.md)）。
ツールが使用できないときは、パスを Read で参照する。

止める案内の例:

```text
この操作に関連する未読のルールがあります。下のルールを参照してから、同じ操作を再試行してください。
`ツール:` の行があるルールは、そのツールで参照してください。記載の引数は全て指定し、「省略可」の引数とその他の引数は任意です。ツールを使用できない場合と、`ツール:` の行が無いルールは、パスを Read で参照してください。
- /home/user/knowledge/docs/rule/python-core-naming.yaml
  ツール: mcp__plugin_dev-docs_dev-docs__search_docs {"source": "knowledge", "filter": {"field": "id", "op": "eq", "values": ["python-core-naming"]}, "view": "full"}（省略可: {"sections": ["命名"]}）
- /home/user/rules/git.md
```

`ツール:` の行が無い案内では、2 行目が「パスを Read で参照してください。」になる。

## 既読の記録

Read か Bash の `cat` `bat` `less` `more` で、索引に載ったルールのファイルを読んだとき、`PostToolUse` フックが、セッションごとの記録ファイル（[設定ファイル](設定ファイル.md)の `global.state_dir`）へ場所を 1 行ずつ追記する。
Bash で読んだファイルは、`## 案内` と同じ規則（引用符の外の glob の展開、`for` の単語の並び）で取り出す。
Read は、ファイルの先頭から末尾までを読んだときだけ既読にする。
`offset`・`limit` で一部だけを読んだときは既読にしない。

MCP のツールの結果に載った文書のうち、`scope` が `full` のルールの文書も、同じ記録へ追記する（[MCPの結果の書式](MCPの結果の書式.md)）。
結果に書式に従う文書が無いときは、索引の `read_by` にヒットする MCP のツールの呼び出しで、そのエントリのルールの場所を追記する（[索引の書式](索引の書式.md)）。
索引の `read_tool` に一致する呼び出しは、結果の範囲と `read_by` によらず、そのエントリのルールの場所を追記する。

記録には、場所と一緒に、既読にした時点のルールの本文のハッシュを残す。
案内するときに今の本文のハッシュと比べ、違えば未読として扱う。
読んだ後にルールが変わると、次にヒットしたときにまた案内される。

記録は、常駐の MCP サーバーのツールで確認・削除できる（[MCPサーバー](コアコンセプト-MCPサーバー.md)・[MCPツール](MCPツール.md)）。
`get_read_records` は、セッションごとの既読のルールの場所と、今の本文が既読にした時点と同じか、読んだ方法を返却する。
`delete_read_records` は、そのセッションの既読の記録と案内済みの記録を削除する。
次のフックの呼び出しから、削除したルールは未読として案内される。
既読の履歴は削除しない。

## 既読の履歴

既読にするたびに、セッションごとの履歴ファイル（`{session_id}.history.jsonl`）へ 1 行追記する。
フックは履歴を読まない。
MCP サーバーの `get_read_records` だけが、読んだ方法を返却するために履歴を読む。

- Read・Bash・MCP のツールのどの読み方で既読にしたときも残す
- 1 行は、時刻・セッション・読み方（`read`・`bash`・`mcp`）・ツール名・ルールの場所を持つ JSON
- 同じ場所を何度読んでも、そのたびに残す

## 圧縮での破棄

`PreCompact` フックが、圧縮の前にそのセッションの記録ファイルと案内済みの記録を捨てる。
削除されたルールは、次にヒットしたときにまた案内される。
既読の履歴は捨てずに残す。

圧縮しないまま終わったセッションの記録ファイルは、終わった後も残る。
`SessionStart` フックが、セッションの開始時に、最後に追記してから `record_retention_days`（既定 30）日を過ぎた記録ファイル・案内済みの記録・既読の履歴を削除する（[設定ファイル](設定ファイル.md)）。

## 案内できないとき

- 設定ファイルが読めないときは、既定値でも動かさず、索引を読まずに、操作を止めずに、設定ファイルの場所と理由をコンテキストへ記載する（[設定ファイル](設定ファイル.md)）
- 索引が読めない・記録ファイルが読めないときは、操作を止めずに、場所と理由をコンテキストへ記載する
- 読めない正規表現を記載したエントリは、そのエントリだけを読み飛ばし、索引の場所・パターン・理由をコンテキストへ記載する
- `rule` が URL のエントリは、Read で読めないため案内にも既読にも使用せず、そのエントリだけを読み飛ばし、索引の場所・`rule`・Read で読めない旨をコンテキストへ記載する
- 既読の履歴にだけ記載できないときは、既読にして操作を止めずに、記載できなかった場所と理由をコンテキストへ記載する
- フックの実行が 1 秒を超えると、Claude Code がフックを打ち切り、案内なしで通常の流れへ進む
