# 設定ファイル

設定ファイルのキーと、`global`・`projects` の適用の仕方と重ね方

利用者ごとの設定は、`${XDG_CONFIG_HOME:-~/.config}/rule-inject/settings.yaml` の YAML で受け取る。
既定と違う場所に配置するときは、環境変数 `RULE_INJECT_CONFIG` で指す（[環境変数](環境変数.md)）。
必要なキーの一覧は、プラグインの直下の [settings.sample.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/settings.sample.yaml)。

設定ファイルの中身は、フックが呼ばれるたびに読み直すので、変えた内容は次の呼び出しから有効になる。
ファイルが無いときは、全てのキーを既定値で動かす。

最上位に `version` と `global` と `projects` を配置する。
`version` は最後に移し替えたツールのバージョンで、スキル `global-setup` が記載する。

```yaml
version: 0.2.3
global:
  indexes:
    - ~/rules/index.yaml
projects:
  - match: my-project
    indexes:
      - rules/project.yaml
```

## global

どのプロジェクトで起動しても有効な値。

<!-- table: data -->

| キー | 型 | 内容 | 既定値 |
| --- | --- | --- | --- |
| `indexes` | 文字列のリスト | どのプロジェクトでも読む索引のパスの並び。絶対パスか `~` で始まるパス | `${XDG_CONFIG_HOME:-~/.config}/rule-inject/rules.yaml` |
| `state_dir` | 文字列 | セッションごとの既読の記録ファイル・案内済みの記録ファイル・既読の履歴ファイルを配置するフォルダ。絶対パスか `~` で始まるパス | `${XDG_STATE_HOME:-~/.local/state}/rule-inject` |
| `log_dir` | 文字列 | 失敗した操作を記載するログのフォルダ。絶対パスか `~` で始まるパス | `RULE_INJECT_STATE_DIR` があればその下の `logs`、無ければ `${XDG_STATE_HOME:-~/.local/state}/rule-inject/logs` |
| `record_retention_days` | 整数 | 既読の記録ファイル・案内済みの記録ファイル・既読の履歴ファイルを残す日数。1 以上 | `30` |
| `log_retention_days` | 整数 | ログのファイルを残す日数。1 以上 | `3` |
| `dev_docs_url` | 文字列 | `check_indexes` が使われているタグを取得する dev-docs の MCP サーバーの URL。`http://` か `https://` で始まる | `http://127.0.0.1:8781/mcp` |
| `server_service` | 文字列 | セッションの開始時に応答しない MCP サーバーを起動する、systemd のユーザーのユニットのサービス名。1〜64 文字の英数字・`_`・`-`（`.service` を付けない）。`global-setup` がユニットを配置したときに記載する | `rule-inject` |

<!-- /table -->

`indexes` 以外の `global` のキー（`state_dir`・`log_dir`・保持日数・`dev_docs_url`・`server_service`）は全てのプロジェクトで共通で、`projects` に配置できない。
環境変数 `RULE_INJECT_STATE_DIR` があるときは、`state_dir` より優先する。
MCP サーバーのポートは設定ファイルに配置せず、環境変数 `RULE_INJECT_PORT` で指す（[環境変数](環境変数.md)）。
`dev_docs_url` もフックが使用せず、`check_indexes` が呼ばれるたびに読むので、変えた内容は次の呼び出しから有効になる。

## projects

要素ごとに `match` と、そのプロジェクトで有効な値を持つ並び。

| キー | 型 | 内容 | 既定値 |
| --- | --- | --- | --- |
| `match` | 文字列 | その要素を適用するプロジェクト。絶対パスかプロジェクト名。必須 | なし |
| `indexes` | 文字列のリスト | ヒットしたプロジェクトだけで読む索引のパスの並び。絶対パス・`~` で始まるパス・プロジェクトの直下（環境変数 `CLAUDE_PROJECT_DIR`）からの相対パス | `${CLAUDE_PROJECT_DIR}/rules.yaml` |

要素が持てるキーは `match` と `indexes` だけで、ほかのキーは設定ファイルの誤りになる。

### 適用の仕方

`match` は、起動したプロジェクトの直下（`CLAUDE_PROJECT_DIR`）に次のとおりヒットする。

| `match` | ヒットする条件 |
| --- | --- |
| 絶対パス | `CLAUDE_PROJECT_DIR` がそのパスか、その配下のとき |
| プロジェクト名 | リポジトリのフォルダ名が一致したとき |

`.claude/worktrees/` の下の worktree は、本体のパスとフォルダ名で確認する。

### 重ね方

ヒットした要素の `indexes` を、並びの順に `global.indexes` の後ろへ追加する。
全てのエントリを合わせて適用する。

### 既定の配置場所

`indexes` を記載しないときは、既定の配置場所の索引を読む。
既定の配置場所にファイルが無いとき（プロジェクトの索引は `CLAUDE_PROJECT_DIR` が無いときも）は、何も通知せずに読まない。
`global.indexes` を空の並び `[]` にすると、ユーザーの既定の配置場所も読まない。
ヒットした要素のどれかが `indexes` を持つときは、空の並び `[]` でも、プロジェクトの既定の配置場所を読まない。

### 相対パス

`projects` の `indexes` の相対パスは、`CLAUDE_PROJECT_DIR` から解く。
Claude が `cd` した先へ動く作業フォルダは基準に使用しない。
`global.indexes` の相対パスは設定ファイルの誤りになる。

索引の中身は [索引の書式](索引の書式.md)。

## 既読の記録の配置場所

`state_dir` には、絶対パスか `~` で始まるパスを記載する。
フォルダが無ければフックが作る。
記録ファイルは `{state_dir}/{session_id}.txt` で、1 行に 1 つのルールの場所を持つ。
最後に追記してから `record_retention_days` 日を過ぎた記録ファイルは、セッションの開始時に削除される（[ルールの案内](コアコンセプト-ルールの案内.md)）。

同じフォルダの `{session_id}.guided.txt` には、止めずに案内したルールの場所を 1 行ずつ持つ。
既読の記録と同じく、圧縮の前とセッションの開始時の掃除で削除される。

同じフォルダの `{session_id}.history.jsonl` には、既読にした履歴を 1 行ずつ持つ（[ルールの案内](コアコンセプト-ルールの案内.md)）。
圧縮の前には削除されず、最後に追記してから `record_retention_days` 日を過ぎたものが、セッションの開始時の掃除で削除される。

## ログの配置場所

`log_dir` には、絶対パスか `~` で始まるパスを記載する。
フックは、失敗した操作をこのフォルダの `{yyyymmdd}_rule-inject.log`（日付は UTC）へ 1 行ずつ記載する。
日付が今日から `log_retention_days` 日以上前のファイルは、セッションの開始時に削除される。

## 設定ファイルの誤り

読む設定ファイルが次のいずれかのとき、設定ファイルの誤りとして扱う。

- `RULE_INJECT_CONFIG` が指すファイルが無い
- ファイルが読めない
- YAML として読めない・UTF-8 として読めない
- 知らないキーや、キーの表の値の範囲の外の値を持つ
- `match` を持たない `projects` の要素がある
- 廃止した `global.server_port` を持つ。理由にスキル `global-setup` での移し替えを示す

誤りのとき、設定ファイルを使用せず、既定値でも動かさない。
索引は読まず、掃除は何も削除しない。
ルールを案内するフックは、操作を止めずに、設定ファイルの場所と理由をコンテキストへ記載する。
各フックは、失敗した操作 `read_settings` を既定のログのフォルダ（`${XDG_STATE_HOME:-~/.local/state}/rule-inject/logs`）へ追記する。
常駐の MCP サーバーは、起動のときは待ち受けずに標準エラーへ場所と理由を記載して 0 以外の終了コードで終わり、ツールの呼び出しのときは `isError: true` で場所と理由を返却する。
