# 索引の書式

ルール索引の YAML のキー

索引は利用者が記載する YAML で、配置場所と名前は自由。
設定ファイル（[設定ファイル](設定ファイル.md)）で指す。
フックは、次のキーとマップ・文字列のリスト・文字列の形式だけを読む。

```yaml
default_on: [read, write, mcp]
rules:
  - rule: ./python.md
    paths:
      - "**/*.py"
    exclude:
      - "**/tests/**"
    on: [write]
  - rule: ./github.md
    tools:
      - "mcp__*__create_*"
  - rule: ./knowledge.md
    tools:
      - "re:__search_docs$"
    args:
      filter[kind]:
        - rule
      filter[tags]:
        - "re:^python"
    read_by:
      - tools:
          - "mcp__docs__get_doc"
        args:
          id:
            - "re:^python"
  - rule: ~/knowledge/docs/rule/python-core-naming.yaml
    paths:
      - "**/*.py"
    read_tool:
      tool: mcp__plugin_dev-docs_dev-docs__search_docs
      args: '{"source": "knowledge", "filter": {"field": "id", "op": "eq", "values": ["python-core-naming"]}, "view": "full"}'
      optional_args: '{"sections": ["命名"]}'
  - rule: ./next.md
    paths:
      - "**/*.tsx"
    enabled: false
```

## 索引のキー

| キー | 型 | 必須 | 既定値 | 内容 |
| --- | --- | --- | --- | --- |
| `default_on` | `read` / `write` / `mcp` のリスト | - | `[read, write, mcp]` | エントリが `on` を記載しないときの、操作を止める操作の種別 |
| `rules` | エントリのリスト | - | - | ルールごとのエントリ |

## エントリのキー

<!-- table: data -->

| キー | 型 | 必須 | 既定値 | 内容 |
| --- | --- | --- | --- | --- |
| `rules[].rule` | 文字列 | ✅ | - | ルールの本文の場所 |
| `rules[].enabled` | `true` / `false` | - | `true` | エントリを照合に使用するか。`false` のエントリは案内にも既読にも使用しない |
| `rules[].paths` | 文字列のリスト | - | なし（パスでは適用しない） | 操作の対象の絶対パスに適用する glob か正規表現 |
| `rules[].exclude` | 文字列のリスト | - | なし（除外しない） | `paths` にヒットしても、このパターンにヒットするパスにはそのエントリを適用しない |
| `rules[].tools` | 文字列のリスト | - | なし（ツール名では適用しない） | MCP のツールの完全名に適用する glob か正規表現 |
| `rules[].args` | キー → 文字列のリストのマップ | - | なし（引数では絞らない） | `tools` にヒットした MCP のツールの引数に適用する glob か正規表現。記載した全てのキーの値がヒットするときだけエントリを適用する |
| `rules[].on` | `read` / `write` / `mcp` のリスト | - | `default_on` | 未読のときに操作を止める操作の種別。ヒットした操作がここに無ければ、止めずに案内する |
| `rules[].read_by` | 要素のリスト | - | なし（MCP のツールの呼び出しでは既読にしない） | そのルールを既読にする MCP のツールの呼び出し。要素のどれか 1 つにヒットした呼び出しが終わった後に、そのセッションの既読にする |
| `rules[].read_by[].tools` | 文字列のリスト | ✅ | - | 既読にする MCP のツールの完全名に適用する glob か正規表現 |
| `rules[].read_by[].args` | キー → 文字列のリストのマップ | - | なし（引数では絞らない） | 同じ要素の `tools` にヒットした呼び出しの引数に適用する glob か正規表現。記載した全てのキーの値がヒットするときだけ既読にする |
| `rules[].read_tool` | マップ | - | なし（案内はパスを Read で参照する旨だけ） | ルールを参照する MCP のツールと引数。案内に記載し、一致する呼び出しで既読にする |
| `rules[].read_tool.tool` | 文字列 | ✅ | - | MCP のツールの完全名（`mcp__` で始まる）。パターンとしては読まない |
| `rules[].read_tool.args` | 文字列（JSON のオブジェクト） | - | なし（引数を指定せずに呼ぶ） | 既読の判定に使用する引数 |
| `rules[].read_tool.optional_args` | 文字列（JSON のオブジェクト） | - | なし | 案内に「省略可」として記載し、既読の判定には使用しない引数 |

### rule

記載できるのは次の場所。

| 場所 | 例 |
| --- | --- |
| 絶対パス | `/home/user/rules/python.md` |
| `~` で始まるパス | `~/rules/python.md` |
| 索引ファイルのフォルダからの相対パス | `./python.md` |

`http://` か `https://` で始まる URL は、案内にも既読にも使用せず、そのエントリを読み飛ばす。
索引の場所・`rule`・Read で読めない旨がコンテキストに載る。
`rule` が無いエントリがあると、その索引を読まず、索引が読めないときと同じく索引の場所と理由がコンテキストに載る。

`rule` には `!{名前}`（名前は `[A-Za-z_][A-Za-z0-9_]*`）を記載できる。
同じ名前の環境変数の値に置き換えてから場所を解く（例 `!{RULES_DIR}/python.md`）。
空の値は空文字に置き換える。
設定されていない名前が残ったエントリは読み飛ばし、索引の場所・`rule`・展開できない名前がコンテキストに載る。

### enabled

`false` のエントリは照合に使用しない。

- ヒットするファイル・MCP のツールを操作しても、止める案内も止めない案内も出さない
- `read_by` にヒットする呼び出しと、そのエントリのルールを Read・Bash で読んだときは、既読にしない
- 同じルールの場所を指す有効なエントリが別にあれば、そのエントリで照合する
- 展開できない名前・URL・読めない正規表現があっても、読み飛ばしの理由はコンテキストに載らない
- `true` / `false` 以外の値は、その索引を読めなくする（索引の場所と理由がコンテキストに載る）

### paths と exclude

`**/` か `*` で始まる glob を記載する。
`**` はフォルダをまたぐ。
照合は操作の対象の絶対パスに対して行う。

### tools

`mcp__` で始まる glob を記載する（例 `mcp__*__create_*`）。
`paths` と `tools` は別々に照合され、記載しなかった方はヒットしない。

### args

`tools` にヒットした MCP のツールの呼び出しにだけ適用する。
キーは引数の名前で、オブジェクトの子はドットで結ぶ（例 `filter.kind`）。

- 記載した全てのキーについて、値がリストのどれかのパターンにヒットするときだけエントリを適用する
- キーが引数に無いとき、値がオブジェクトのときは適用しない
- 値が配列のとき、およびドット区切りのキーの途中が配列のときは、要素ごとに照合し、どれか 1 つがヒットすれば適用する
- 文字列以外のスカラーは JSON の表記（`true`・`null`・`1.5`）の文字列にして照合する

条件の木（`field`・`op`・`values` の条件と、`and`・`or`・`not` の束を入れ子にした引数。dev-docs の `search_docs` の `filter` など）の中の値は、`{道筋}[{field}]` のキーで適用する（例 `filter[tags]`・`filter[kind]`）。

- 道筋が指す値を条件の木として読み、`and`・`or` の中を深さを問わずたどって、`field` が一致する条件の `values` の要素に照合する
- `not` の中の条件と、`op` が `ne`・`not_contains`・`not_exists` の条件の `values` は照合しない
- 道筋の途中や値が配列のときは、要素ごとにたどる
- 条件の木として読めない値からは値を取らず、照合する値が 1 つも無いキーはヒットしない
- `[` と `]` を含まないキーは、ドットの道筋として読む

`args` は、`キー:` の下にパターンのリストを並べたブロックのマップだけを読む。
`{...}` のマップ・空の `args`・同じキーの重複は、その索引を読めなくする（索引の場所と理由がコンテキストに載る）。

### read_by

結果に文書の場所と範囲を記載しない、[MCPの結果の書式](MCPの結果の書式.md)に従わないツールのための指定で、結果に書式に従う文書があるときは使用しない。
要素のどれか 1 つにヒットした呼び出しが終わった後に、そのエントリのルールをそのセッションの既読にする。
既読になったルールは、案内で操作を止めない。

- `tools` は `rules[].tools` と、`args` は `rules[].args` と同じ記載方法で、引数の照合の規則も同じ
- 案内用の `tools`・`args` にヒットしただけでは既読にしない
- `tools` が無い要素があると、その索引を読まず、索引が読めないときと同じく索引の場所と理由がコンテキストに載る

### read_tool

MCP のツールでルールの必要な部分だけを参照させるときに記載する。
案内では、ルールのパスの行の下に `ツール:` の行（ツールの完全名と `args` の JSON。`optional_args` があれば末尾に `（省略可: {JSON}）`）が載る。
ツールが使用できないときは、パスを Read で参照するよう案内する。

- `args`・`optional_args` は、JSON のオブジェクトを単一引用符で囲んだ文字列で記載する。JSON として読めない・オブジェクトでない値は、その索引を読めなくする（索引の場所と理由がコンテキストに載る）
- 呼び出しのツール名が `tool` と同じで、`args` に記載した全てのキーが呼び出しの引数にあり、値が JSON の値として等しいときに、結果の範囲と `read_by` によらず、そのエントリのルールをそのセッションの既読にする
- 値の比較では、オブジェクトはキーの順を問わず、配列は順まで比べ、真偽値と数値を区別する
- 呼び出しが `args` に無いキーを持っていても、`optional_args` の値と違っても既読にする。`sections`・`fields` のように範囲を絞る引数は `optional_args` に、どの文書を参照するかを決める引数は `args` に記載する
- 同じルールのパスに複数のエントリがヒットしたときは、`read_tool` を重複を除いてまとめて記載する
- `read_tool` は案内と既読にだけ使用し、操作を止めるかの照合には使用しない

### 正規表現

`paths`・`exclude`・`tools`・`args` のパターンは、`re:` で始めると正規表現になる。
`read_by` の `tools`・`args` のパターンも同じ。
`re:` の後ろを Python の正規表現として、対象の文字列に部分一致（`re.search`）で照合する。
全体に適用するときは `^` と `$` を記載する。
`re:` で始まらないパターンは、glob として読む。

読めない正規表現を記載したエントリは読み飛ばし、索引の場所・パターン・理由がコンテキストに載る。
同じ索引のほかのエントリは読む。

### on

| 値 | 操作 |
| --- | --- |
| `read` | Read、Grep、Bash での読み取り |
| `write` | Edit、Write、NotebookEdit |
| `mcp` | MCP のツールの呼び出し |

同じルールの場所に複数のエントリがヒットしたときは、案内を 1 件にまとめ、どれか 1 つでも止めるなら止める。
場所は、解決後の絶対パスか URL で同じものを同じルールとして数える。

## JSON Schema

索引のキーと値の範囲は、JSON Schema 2020-12 を YAML で記載した `src/rule_inject/features/index/check/index.schema.yaml` が持つ。
常駐の MCP サーバーのチェックのツール `check_indexes` が、この Schema に索引を照らし、違反を `rules[0].paths` のような索引の中の場所と理由で返却する（[MCPツール](MCPツール.md)）。
`rule` の場所にファイルが無いエントリも、同じツールが返却する。

Schema が受け付ける範囲は、フックの読み取りが受け付ける範囲の内側にある。
例えば `paths: []` はフックが読めるが、Schema は要素を 1 つ以上求めるため違反になる。
フックは Schema を使用せず、このページのキーだけを読む。
