## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ログのファイル | 失敗のたびに、その時刻（UTC）の日付の `{yyyymmdd}_rule-inject.log` へ 1 行追記する | 置き場所は `RULE_INJECT_LOG_DIR`（既定 `${XDG_STATE_HOME:-~/.local/state}/rule-inject/logs`） |
| ログの掃除 | セッションの開始時（`SessionStart`）に、既読の記録の掃除と同じフックで、ファイル名の日付が今日から保持日数以上前のログのファイルを消す | 保持日数は `RULE_INJECT_LOG_RETENTION_DAYS`（既定 3） |
| 既読の記録の保持期間 | `RULE_INJECT_RECORD_RETENTION_DAYS`（既定 30）で変えられる | 利用者の回答で、この PR に含める |
| 不正な値 | 日数の環境変数が 1 以上の整数でないときは既定値で動く | 利用者の回答で決めた（[確認ログ](./確認ログ.md)） |
| ログの書き先 | ログを書く全ての呼び出し元（フック・MCP サーバー）は `log_dir(env)` を渡し、案内文に出すログの場所は `log_file_path(log_dir(env), 今日)` にする | `LOG_FILE_NAME` は廃止 |
| 対応テストファイル | モジュール構成『共通』『フック』の `test_files` は、テストの作成までの間は外している | 単体テスト作成で、既存のテストファイルと `tests/unit/rule_inject/shared/test_settings.py` を戻す |
| 消している間の追記 | 書き足すのは今日の日付のファイルだけで、消すのは過去の日付のファイルだけなので、同じファイルに当たらない | 錠は要らない |
| 変更前のログ | 記録フォルダに残った `rule-inject.log` を、最終更新によらず同じ掃除で消す | どの利用者の手元にも残らない |
| 掃除の失敗 | 操作を止めず、ER 図「ログ」の形でログへ 1 行書く（`delete_log`）。書けなければ標準エラー出力へ出す | 既存のフックと同じ |
| 実行時間 | 既読の記録の掃除と合わせてフックの 1 秒に収める | ファイル名だけで決め、中身は読まない |
| セットアップ | ログのフォルダと保持日数・既読の記録の保持期間を変える段を、任意の手順として足す | - |

### 論点: ログの古い内容の消し方

大きさの上限で 1 世代前へ付け替える案で確認事項を出したところ、利用者の回答で日付ごとのファイルに分けて保持日数で消す形に決まった（[確認ログ](./確認ログ.md)）。
