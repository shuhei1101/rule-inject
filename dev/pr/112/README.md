# 常駐の MCP サーバーが落ちていたとき、SessionStart のフックで起動を補助する

## 概要

常駐の MCP サーバーが応答しないとき、セッションの開始時に SessionStart のフックがサーバーの起動を補助する。

## 背景

[Issue #111](https://github.com/shuhei1101/rule-inject/issues/111) の要望。
常駐の MCP サーバーが止まっていると、セッションを開いても起動されず、Claude Code は接続の失敗を表示したまま MCP のツールを使用できない。
規約『MCP サーバー作成ルール』の `sdk-transport-06` と規約『ローカルサーバーの立て方』の `resident-01` は、起動と管理を systemd --user で行い、SessionStart のフックを落ちていたときの起動の補助にすると定めている。
今の `hooks/hooks.json` の SessionStart は作業の決まりの注入（`work_rules`）と既読の記録の掃除（`sweep_read`）だけで、起動を補助するフックが無い。
同じ規約の項目のうち、管理の MCP ツール（状態の確認・再読込・再起動・更新）は [PR #110](https://github.com/shuhei1101/rule-inject/pull/110)（起点 [Issue #107](https://github.com/shuhei1101/rule-inject/issues/107)）で入った。
