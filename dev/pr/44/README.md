# MCP サーバーを stdio から HTTP の常駐サーバーに移す（既定のポート 8783・RULE_INJECT_PORT）

## 概要

並行で起動した Claude Code のセッションが、1 つの常駐の MCP サーバー（Streamable HTTP）を共有して `read_rules` を呼べるようになる。
待ち受けのポートは既定で 8783 とし、環境変数 `RULE_INJECT_PORT` で上書きできる。

## 背景

[Issue #36](https://github.com/shuhei1101/rule-inject/issues/36) の要望。
MCP サーバーは `.mcp.json` の `uv run ... python -m rule_inject.server` で stdio で起動しており、セッションごとにサーバーのプロセスが立ち、依存解決も毎回走る。
セッションを並行で起動することが多く、プロセスがセッションの数だけ増える。
knowledge のワークスペース `tmp/mcpベストプラクティス検討` の D-60（全リポジトリで MCP サーバーを HTTP の常駐サーバーにし stdio を禁止する）と D-61（リポジトリごとの既定のポートと `{リポジトリ}_PORT` での上書き）で決め、knowledge の『MCP サーバー作成ルール』に [shuhei1101/knowledge#50](https://github.com/shuhei1101/knowledge/issues/50) で入った。
