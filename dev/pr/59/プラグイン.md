## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| サーバーの置き場所 | フックと同じリポジトリの `src/rule_inject/server/` に置き、ローカルのクローンから起動する | 起動と停止の方法は `要件.md` の `未確定` |
| 設定 | フックと同じ設定ファイルに待ち受けのポートのキーを追加する。サーバーは起動時の `RULE_INJECT_CONFIG` で同じファイルを読む | キーの名前・置く階層（`global` 等）・既定値は設定の設計で決める |
| プロジェクトの解決 | 一覧・検索のツールはプロジェクトの直下のパスを引数で受け、フックの `CLAUDE_PROJECT_DIR` と同じ規則で `projects[].match` を当てる | サーバーはセッションを持たないため |
| 照合 | 検索のツールは `features/index` の照合をそのまま使い、フックと同じ結果を返す。既読の記録は見ない | 止めるかは未読とみなしたときの結果 |
| 環境変数 | サーバーは Claude Code の外で起動するため、フックが Claude Code の設定の `env` で受け取る環境変数（`RULE_INJECT_CONFIG`・索引の `!{名前}` の変数・`XDG_CONFIG_HOME`・`XDG_STATE_HOME`）を、起動の側にも置く前提にする | 使い方と `docs/リファレンス/環境変数.md` に記載する。一覧・チェックのツールの応答に、サーバーが読んだ設定ファイルの場所を載せる |
| 索引のスキーマ | 索引のキーと値の範囲を JSON Schema（YAML）で持ち、チェックと編集の検証に使う | 索引の書式（`docs/リファレンス/索引の書式.md`）と食い違わないことをテストで確かめる |
| 編集の範囲 | 編集のツールが書き込めるのは、設定ファイルで読む索引に限る | 任意のファイルへの書き込みを防ぐ |
| フックの依存の読み込み | フックは今どおり標準ライブラリだけで動き、サーバーの依存（`mcp`・`jsonschema`）を読み込まない | - |

`未確定`: 常駐の MCP サーバーを新しいサブシステムにするか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | アーキテクチャ図に新しいサブシステム「MCP サーバー」を追加し、計画書を分ける | 動くプロセス・依存・テストの範囲がフックと分かれ、責務の境界が読み取れる | サブシステムの増加はエスカレーションが要る |
| B | プラグインのサブシステムに含める | サブシステムの構成が変わらない | 「標準ライブラリだけ」「常駐しない」の制約がサブシステムの一部にだけ当たる |

推奨: A

サーバーは別のプロセスで常駐し、標準ライブラリ以外に依存するため、フックの制約と分けて書かないと、どちらの制約がどこに当たるか読み取れない。
A に決まったら、この計画書のサーバーの行を `MCPサーバー.md` へ移す。
