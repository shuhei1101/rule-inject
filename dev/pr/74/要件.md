# 要件

## 要望

AI Monitor の配布物の準拠バージョンを v0.2.0 から v0.3.0 へ上げ、追従 Issue の分類ごとに次を満たす。

| 分類 | 満たすこと |
| --- | --- |
| テンプレート | `dev/テンプレート/` が持つ `*.schema.yaml` の全ファイルが v0.3.0 のタグの同じパスのファイルと一致する。`python -m ai_monitor.design_docs convert --from v0.2.0 --to v0.3.0` を流し、続けて `validate` が誤り 0 件で通る。`dev/テンプレート/README.md` を `publish` で生成し直す |
| サイトのレイアウト | `python -m ai_monitor.distribution import-site --version v0.3.0` で `docs/_theme/` を取り込み、控え `ai-monitor-theme.yaml` が v0.3.0 を指す |
| 配信設定 | `docs/_config.yml` を新しく置き、v0.3.0 の配布元の `docs/_config.yml` のキーを rule-inject の値（`title`・`description`・`baseurl: /rule-inject`）で持つ。公開サイト <https://shuhei1101.github.io/rule-inject/> が取り込んだレイアウトで描画される |
| 規約・外部規約・判定・観点 | v0.2.0..v0.3.0 で変わった規約・コーディング規約・判定フローチャート・チェックシート・観点を読み直し、従っていない rule-inject の成果物（`dev/`・`docs/`・ルートの `README.md`・`CLAUDE.md`）を修正する |
| 準拠バージョン | [ai-monitor-version.ini](https://github.com/shuhei1101/rule-inject/blob/develop/ai-monitor-version.ini) が `v0.3.0` を指す |

`convert --from` に渡すバージョンは v0.2.0 にする。
v0.3.0 のタグの変換の一覧 `dev/テンプレート/変換/versions.yaml` は v0.4.0 の変換しか持たず、v0.2.0..v0.3.0 の間に当てる変換は無い。
develop の設計書を v0.3.0 の Schema に差し替えて `validate` を流すと誤りは 0 件で、`dev/pr/` を除く設計書は v0.3.0 の Schema に合っている。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| フェーズ手順の読み直し | rule-inject は固有のエージェント・フェーズを持たず、共通のフェーズ手順は AI Monitor から実行時に読むため、リポジトリに変える成果物が無い | 予定なし |
| ルール索引の行の追加 | 配布元のルール索引 `rules.global.yaml` は AI Monitor が全プロジェクトに直接当て、配布先へコピーしない。[docs/rules.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/docs/rules.yaml) は rule-inject 自身のルールの索引で、配布元の行を持たない | 予定なし |
| プラグインの取り直し（MCP `update_plugins`） | 手元の ai-monitor プラグインは 2026-10-29 16:04（UTC）に取り直し済みで、v0.3.0 のタグ（2026-10-28）より後になっている | 予定なし |
| `settings.yaml` の新しいキーの追加・`agents[].mcp_tools` の見直し | `settings.yaml` は AI Monitor 本体の設定で、rule-inject のリポジトリに無い | 予定なし |
| v0.3.0 で増えた `開発コマンド.schema.yaml`・`フェーズ.schema.yaml` を `dev/テンプレート/` へ追加する | rule-inject は開発コマンドの設計書もフェーズの YAML も持たない。追加するかは判断が分かれるため、レビューで確定する（今の判断: 追加しない） | 予定なし |
