# 要件

## 要望

### 条件の木の中の値への照合

- 索引の `args`（`rules[].args` と `rules[].read_by[].args`）で、MCP のツールの引数の条件の木（dev-docs の `search_docs` の `filter`）の中の「`field` が X の条件の `values`」に当てられるようにする
  - 条件の木は、`{"field": ..., "op": ..., "values": [...]}` の条件と、`and`・`or`・`not` の束を入れ子にしたもの（dev-docs の develop の `src/dev_docs/features/search/types.py` の `Condition`・`Group`）
  - 入れ子の `and`・`or` の中の条件も見る
  - タグ（`field: tags`）と文書の種類（`field: kind`）のどちらにも当てられる
  - 書き方は `{道筋}[{field}]` のキー（例 `filter[tags]`）
- 今のドットの道筋の書き方（`filter.kind` のようなキー）は残し、今の索引の照合の結果を変えない
- フックの読み取りと JSON Schema（`index.schema.yaml`）の両方で新しい書き方を受け付け、`write_index_entry` で書ける

`not` の束の中の条件と、`op` が `ne`・`not_contains`・`not_exists` の条件には当てない（インターフェース定義設計で案 A に決定）。
除く検索は読み手がそのタグの文書を読まない検索で、ルールを読ませる理由が無いため。

### 索引の書式の例と説明の修正

- `docs/リファレンス/索引の書式.md` の例（`kind`・`filter.tags`）と `### args` の説明を、dev-docs の今の `search_docs` の引数（条件の木の `filter`）に合わせて直す

### 使われていないタグのパターンの警告

- 索引のチェック（`check_indexes`）で、タグに当てるパターンが dev-docs で使われているどのタグにも当たらないエントリを警告する
  - 使われているタグは、dev-docs の `search_docs` の `group_by: tags` で引く（配信元をまたぐときは `source: *`）
  - dev-docs のタグは正規化（NFKC と `casefold`）してから数えられる。パターンは、返ったタグか正規化したタグのどちらかに当たれば使われているとする
  - 警告は、#64 の `paths` の当たらないエントリの検出と同じく `check_indexes` の応答に載せる
  - dev-docs に届かないときは、この確かめを飛ばし、飛ばしたことと理由を応答に載せる。ほかの問題の種類の判定と応答は変えない
- dev-docs の接続先は設定から決める（今の設定は自分が待ち受ける `server_port` だけを持つ）
- 書き込み前の検証（`write_index_entry`・`delete_index_entry`）には含めない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| タグ以外の項目（`kind` など）のパターンが、使われているどの値にも当たらないことの警告 | 要望はタグのパターンの警告で、dev-docs が集計して返すのもタグの語彙として使う `group_by: tags` | 予定なし |
| タグのマスター（説明・aliases・deprecated・未登録の検出） | D-169 でマスターを持たないと決めた | 予定なし |
| ドットの道筋の書き方の廃止 | 今の索引の照合の結果を変えないため残す。廃止すると破壊的変更になる | 予定なし |
| 非機能要件「dev-docs への問い合わせの待ち時間」の p99.9 を 1,000 回の実測で置き直す | 1 回 30〜70 秒かかり、測るだけで 10 時間以上かかる。実測 22 回の最大を仮の p99.9 にして進めることをユーザーが承認した | [#78](https://github.com/shuhei1101/rule-inject/issues/78) |
