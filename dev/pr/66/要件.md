# 要件

## 要望

規約・手順を書いたときに、rule-inject の索引（rules.yaml）へ登録して注入するか、dev-docs の文書にしてタグで読ませるかを決める判定フローチャートを、公開ドキュメントの使い方に追加する。

- 判定の軸は、話し合い（A-16・D-92・D-107・D-110）で決めた「強制注入を残す基準」の 4 つにする
  1. 読まずに編集すると、後から直すのに手間が掛かる（書式・AI の既定と逆の独自の決まり・安全）
  2. 機械検査で判定できない（lint・スキーマ・型検査で判定できる部分は検査へ移す）
  3. glob が狭い（拡張子だけの glob は全言語共通の規約 1〜2 件に限る）
  4. 短い（1 ルール 4KB 以内。1 ファイルの編集で当たる合計は 10KB 以内。テンプレートは例外）
- 終端は次の 3 つにする
  - 4 つをすべて満たす → rules.yaml に `on: [write]` で登録する
  - 機械検査で判定できる部分がある → その部分を検査へ移し、本文から削って残りを判定し直す
  - どれかを満たさない → rules.yaml から外し、dev-docs の文書にしてタグを付ける
- 図はマーメイドの `flowchart TD` で描き、用語は図の直下に `※N` の定義を並べる
- このページ自体は rules.yaml に登録しない（[docs/rules.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/docs/rules.yaml) は空のまま）
