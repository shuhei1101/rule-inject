# 要件

## 要望

モジュール構成の次の 8 つの設計書を、`src/rule_inject/` の物理ファイルごとの設計書へ分ける。

| 設計書 | 分けた後の設計書（`モジュール構成/` の下） |
| --- | --- |
| `MCPサーバー/エントリの編集.py.yaml` | `features/index/edit/{types,_yaml,service}.py.yaml` |
| `MCPサーバー/索引のチェック.py.yaml` | `features/index/check/{types,service,scan,tags}.py.yaml` |
| `プラグイン/MCPの結果の文書.py.yaml` | `features/document/{types,service}.py.yaml` |
| `プラグイン/フック.py.yaml` | `hooks/{__init__,_runner,rule_guide,record_read,search_guide,discard_read,sweep_read,work_rules}.py.yaml` とプラグインの直下の `hooks/run.py` の設計書 |
| `プラグイン/共通.py.yaml` | `shared/{errors,paths,settings,_settings_yaml,variables,logger}.py.yaml` |
| `プラグイン/既読の記録.py.yaml` | `features/record/{types,service}.py.yaml` |
| `プラグイン/案内.py.yaml` | `features/guidance/{types,service}.py.yaml` |
| `プラグイン/索引.py.yaml` | `features/index/{types,_yaml,service}.py.yaml` |

- 分けた後の設計書は、どれも要素の `container` が 1 つの物理ファイルだけを指す
- 要素（列挙・定数・関数型・クラス・データモデル・関数）の中身は変えずに移す
- `test_files` は物理ファイルごとの単体テストのファイルを、その物理ファイルの設計書へ移す
- 構成図・ディレクトリ構成と分類全体の決まり（`lead`・`directory`・`notes`）は、要素を持たない束ねる設計書 `モジュール構成/分類/{MCPサーバー,プラグイン}/{元の設計書の名前}.yaml` に置く
- 8 つの設計書を削除し、目次 `index.yaml`・`src/files.yaml` と `hooks/files.yaml` の `related` の `to`・設計書の中の参照を分けた設計書へ張り直す
- 分けた設計書のどれにも、書くツール `write_design_doc_module` が `物理ファイルが 2 つ以上あります` を返さない

置き場所は #85 と同じく `モジュール構成/{container}.yaml` にする。
プラグインの直下の `hooks/run.py` の置き場所は [プラグイン](./プラグイン.md) の `未確定` で決める。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `shared/yaml_lines.py` の要素（定数・関数）がモジュール構成のどの設計書にも無い | 物理ファイルの設計の欠けで、設計書を分けることとは別の作業。この PR では `src/files.yaml` の `related` を束ねる設計書へ張り直すだけにする | #92 |
| `プラグイン/コマンドの解析.py.yaml` の置き場所が `モジュール構成/{container}.yaml`（`features/command/service.py.yaml`）と揃わない | 物理ファイルは 1 つで書くツールで書き込め、Issue の要望（8 つの設計書の分割）に当たらない。この PR で一緒に移すと `プラグイン/` が空になり目次が揃うため、含めるかはモジュール構成設計のレビューで確定する | 起票予定 |
| プロジェクトの `dev/テンプレート/モジュール構成.schema.yaml` の説明が「1 ファイル = 分類 1 つ」のまま | 配布物の Schema で、AI Monitor の配布物への追従で入れ替わる | 予定なし |
