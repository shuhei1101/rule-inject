# 要件

## 要望

リポジトリの直下に rule-inject の索引 `rules.yaml` を作成し、`RULE_INJECT_INDEXES_PROJECT` が指す索引の読み込みで `FileNotFoundError` が出なくなる。
このリポジトリでファイルを書く・ツールを呼ぶ前に、次のルールが案内される。

| 区分 | 載せるルール | 当てる操作 |
| --- | --- | --- |
| プロジェクト固有のテンプレート | `dev/テンプレート/{種別}.schema.yaml`（設計書の種別ごとの Schema） | 対応する設計書のフォルダ（`**/dev/設計書/{種別のフォルダ}/**`）の書き込みと、dev-docs の `write_docs` で配信元 `rule-inject` のその種別を書く呼び出し |
| プロジェクト固有のリファレンス | [docs/リファレンス/索引の書式.md](https://github.com/shuhei1101/rule-inject/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E7%B4%A2%E5%BC%95%E3%81%AE%E6%9B%B8%E5%BC%8F.md) | 索引 `**/rules.yaml` の書き込み |
| knowledge の規約 | Python のスタックの規約のうち、knowledge の `rules.yaml` に無いもの（命名・型ヒント・言語の決まり・フォルダ構成・ロガー・テストの種類・Mock・静的検査 など） | `**/*.py` と `pyproject.toml` の書き込み |

- knowledge の規約の `rule` は `!{KNOWLEDGE_ROOT}/docs/rule/{ID}.yaml` で書き、`read_tool` に dev-docs の `search_docs`（配信元 `knowledge`・文書の ID）を記載する
- knowledge で廃止予定の規約（`markdown-mermaid`・`markdown-flowchart`）は載せない（[#99](https://github.com/shuhei1101/rule-inject/issues/99) の「古い規約の削除」の対象のため）
- 載せた索引を常駐の MCP サーバーの `check_indexes` に照らし、違反と、`rule` の場所にファイルが無いエントリが 0 件になる

## 影響するユースケース

なし（rule-inject の機能を変えず、このリポジトリの索引にエントリを記載するだけ）
