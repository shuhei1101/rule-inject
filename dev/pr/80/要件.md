# 要件

## 要望

- dev-docs が配信する文書の数ごとに、`search_docs`（`source: "*"`・`group_by: tags`・`format: json`・`cwd` に配信元の中）を 1,000 回呼び、接続から応答までの時間の p99.9 を測る
  - 文書の数は、#77 で測った 2 つの配信元（shuhdev-gateway の 51 件、claude-balancer の 585 件）で分ける
  - 1 回ずつ順に呼ぶ（並べて呼ぶと、互いの負荷で応答までの時間が延びるため）
- 非機能要件「dev-docs への問い合わせの待ち時間」の `value`・`rationale`・`breakdown` を、測った p99.9 のうち大きい方 + その 50% で置き直す（規約『資源の値の決め方』の「下流を待つタイムアウト」）
- 待ち時間が変わる場合は、次も同じ値に置き直す
  - インターフェース定義「索引のチェック」の制約「問い合わせと辿る順」の待ち時間と、1 回の呼び出しの所要時間の上限（待ち時間と辿る時間の大きい方 + 待ち時間の 50%）
  - 定数 `DEV_DOCS_TIMEOUT` と、それを持つモジュール構成の値
  - 公開ドキュメントの `check_indexes` の待ち時間と所要時間の記述

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 1 回の呼び出しの所要時間の上限の余裕（内側の待ち以外の処理）の実測 | Issue の要望は待ち時間の p99.9 の置き直しで、余裕は規約の既定（内側の待ちの 50%）のままにする。余裕を実測で置き直すかは判断が分かれるため、レビューで確定する | 起票予定 |
| モジュール構成「MCPサーバー / サーバー」の物理ファイルごとの設計書への分割 | テンプレート『モジュール構成』の「1 ファイル = 物理ファイル 1 つ」に外れており、書くツールが書き込みを止める（この PR では `DEV_DOCS_TIMEOUT` の値だけを直接編集で修正した）。要望に含まれない | #81 |
| dev-docs の既定の接続先（末尾の `/` の無い `/mcp`）が 405 を返し、`check_indexes` の `tag_check` が常に `skipped` になる | `src/rule_inject/shared/settings.py` の `DEFAULT_DEV_DOCS_URL`・`settings.sample.yaml`・`docs/リファレンス/設定ファイル.md` の不具合で、要望に含まれない | #82 |
| 結合テストのサーバーのポートの取り方（負荷の高いときに他のプロセスとの取り合いで失敗する） | `tests/integration/server/conftest.py` の `free_port`・`_start_shared` の不具合で、要望に含まれない | #83 |
