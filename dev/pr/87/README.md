# 結合テストのサーバーのポートの取り方を修正し、他のプロセスとの取り合いで失敗しないようにする

## 概要

結合テストのサーバー・偽の dev-docs が使うポートを、他のプロセスとの取り合いで失敗しない取り方にし、負荷の高いときも結合テストが安定して通るようにする。

## 背景

[Issue #83](https://github.com/shuhei1101/rule-inject/issues/83) の要望。
[#80](https://github.com/shuhei1101/rule-inject/pull/80) の実装で、load average 22 / 8 コアの間に結合テストが 2 回失敗し、負荷が下がった 3 回目で全 pass した。
失敗したのは `test_server_start.py`・`test_list_rules.py`・`test_search_rules.py` で、サーバーの起動待ちのタイムアウト・別のプロセスが応答した `MCPError: Not Found`・`test_normal_when_port_overridden` で `port_is_listening(config_port)` が `True` のいずれか。
`tests/integration/server/conftest.py` が空いているポートを一度待ち受けてすぐ閉じ、番号だけを渡しているため、閉じてからサーバーが待ち受けるまでの間に他のプロセスが同じポートを取ると失敗する。
