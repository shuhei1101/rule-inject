# 要件

## 要望

dev-docs が `tags` を `- name: ...` の要素で持つ配信元のタグを返したときも、`check_indexes` が使われているタグを正しく扱い、使われているパターンを使われていないと報告しない。

- dev-docs の develop（dev-docs#43 を含む）と knowledge の develop の `dev-docs.yaml`（`metadata` の `tags: tags[].name`）で、`search_docs`（`source: "*"`・`group_by: "tags"`・`format: "json"`・`cwd`: rule-inject のクローン）の `groups[].value` に `{'name': ...}` の値が 0 件である
- 同じ dev-docs へ `check_indexes` を呼び、knowledge の配信元で使われている `topic:*`・`scope:*` のタグのパターンが使われていないと報告されない
- 外部 API『dev-docs』の `groups[].value` の記述と `verification` を、確かめた結果に合わせる

`未確定`: 確かめても `{'name': ...}` の値が残る場合に rule-inject 側で対応するか（決める段: モジュール構成設計）

| 案 | 内容 |
| --- | --- |
| A | dev-docs・配信元の設定の側を修正する Issue を起票し、rule-inject のコードは変えない |
| B | `_parse_tags` で辞書を文字列にした値から `name` を取り出す |

推奨: A

扱いの判断で、dev-docs が修正した後に使われない回避のコードを rule-inject に残さないと決めたため。
