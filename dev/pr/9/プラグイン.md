## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 終わったセッションの記録ファイル | セッションの開始時（`SessionStart`）に、最終更新から非機能要件「既読の記録の保持期間」（30 日）を過ぎた記録ファイルを消す。終わり（`SessionEnd`）では消さない | 始まったセッション自身の記録ファイルは消さない。下の論点の案 A |
| 削除の失敗 | 操作を止めず、ER 図「ログ」の形でログへ 1 行書く | ログにも書けなければ標準エラー出力へ出す（既存のフックと同じ） |
| 実行時間 | 掃除を含めてフックの 1 秒に収める | 記録フォルダの直下の `*.txt` だけを見る |

### 論点: 記録ファイルを消す契機

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 開始時に、保持期間（Claude Code の会話の既定の保持期間と同じ 30 日）を過ぎた記録ファイルを消す | 再開したセッションで、文脈に残っている読んだルールが案内されない | 終わったセッションの記録ファイルが最長 30 日残る |
| B | 終わり（`SessionEnd`）でそのセッションの記録ファイルを消し、SIGKILL などで残ったファイルを開始時に期間で消す | 終わったセッションの記録ファイルがすぐ消える | `/exit`・`/clear` の後に再開したセッションで、読んだルールがまた案内される（PoC の回 4）。止めるルールは読み直すまで操作が止まる |

推奨: A

Claude Code は終えたセッションも会話の保持期間のあいだ再開でき、再開すると読んだルールの本文を文脈に持ったまま同じ `session_id` で続く（[Manage sessions](https://code.claude.com/docs/en/sessions)、PoC の回 4）。
B は再開のたびに読み直しを強い、今の挙動を悪くする。
記録は 1 セッション数 KB で、30 日分残っても容量は問題にならない。

| 回 5: 対話で Read した後に SIGTERM | 観測: `SessionEnd` が届くか | 届いた | [#10](https://github.com/shuhei1101/rule-inject/pull/10)（closed） | `reason: other`、記録ファイルは消えた |
| 回 6: 対話で Read した後に SIGKILL | 観測: `SessionEnd` が届くか | 届かない | [#10](https://github.com/shuhei1101/rule-inject/pull/10)（closed） | 記録ファイルが残った。期間での掃除の対象になる |

仮説は成立で、`SessionEnd` は `-p`・`/clear`・`/exit`・SIGTERM の終わりで同じ `session_id` を持って届き、`/resume` では切り替え元の `session_id` で届く。
ただし回 4 のとおり、終わりで記録を消したセッションを再開すると、同じ `session_id` のまま記録が空から始まり、文脈に残っている読んだルールがまた案内される。
そのため終わりでは消さず、`## 変更方針` の論点の案 A（開始時に保持期間を過ぎた記録ファイルを消す）で設計へ進む。

動かしたのは Claude Code 2.1.284。
tmux のサーバーが別の `CLAUDE_CONFIG_DIR` を持っていたため、対話の最初の試しはログインの切れた設定で起動し、モデルを呼べなかった（`poc/results/trial-not-logged-in.log.jsonl`。このときも `/exit` の `SessionEnd` は `prompt_input_exit` で届いた）。
以降は `CLAUDE_CONFIG_DIR` を渡して起動した。

最小再現の核心は、`SessionEnd` の入力の `session_id` で記録ファイルを消す部分（`poc/plugin/hooks/poc_hook.py`）。

```python
payload = json.load(sys.stdin)
record = state_dir / f"{payload['session_id']}.txt"
existed = record.is_file()
record.unlink(missing_ok=True)
remaining = sorted(path.name for path in state_dir.glob("*.txt"))
```

PR の diff の見どころは次の 2 つ。

- `poc/results/run{N}.log.jsonl`: 回ごとの `PreToolUse` と `SessionEnd` の入力、消す前に記録ファイルがあったか、消した後に残っている記録ファイル
- `poc/results/state-remaining.txt`: 全ての回の後に残った記録ファイル（回 6 の SIGKILL のセッションだけ）
