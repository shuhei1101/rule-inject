# 要件

## 要望

- 常駐の MCP サーバーへ、サーバー自身を管理する次の 4 つの MCP ツールを追加する（規約『MCP サーバー作成ルール』の `sdk-transport-06`）

  | ツール | できること |
  | --- | --- |
  | 状態の確認 | 待ち受けのポート・プロセス ID・起動した時刻・ツールのバージョン・クローンの場所と commit・設定ファイルの場所と読めるかを返す |
  | 設定の再読込 | 設定ファイルを読み直した結果を返す |
  | 再起動 | 応答を返した後に待ち受けを閉じ、起動し直す |
  | 更新 | サーバーのクローンへ上流の commit を取り込み、依存を入れ直して再起動する。設定の移し替えが要るときは再起動せず、`global-setup` を案内する |

- 再起動・更新は、応答を返し終えてから停止を始め、処理中の呼び出しの終わりを待つ間も待ち受けを続ける。結果は、接続し直した後の状態の確認で確かめる
- 再起動の途中の再起動・更新の呼び出しは断る
- 更新は、上流に新しい commit が無いとき・fast-forward できないとき・commit していない変更があるときは、クローンに触らず再起動もしない
- 既存の 7 つのツールの引数と応答は変えない

- 再起動は、待ち受けを閉じた後に `os.execv` で同じプロセスを置き換えて起動し直す（systemd の unit は変えない）
- 設定の再読込は、設定ファイルを読み直し、読めたかと読んだ値（読む索引・記録フォルダ・保持日数・dev-docs の接続先）を返す。待ち受けのポートは比べない
- 管理のツールは、今のツールと同じ `/mcp` に登録する

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| サーバーが落ちていたときの SessionStart のフックでの起動の補助 | 同じ `sdk-transport-06` に当たるが、要望は管理の MCP ツールだけで、フックの変更を含まない | [#111](https://github.com/shuhei1101/rule-inject/issues/111) |
| 他のリポジトリ（alias-inject・mdmark など）の常駐サーバーの管理のツール | 要望は rule-inject のサーバーだけ | 予定なし |
