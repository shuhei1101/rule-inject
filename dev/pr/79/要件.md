# 要件

## 要望

[dev-docs.yaml](https://github.com/shuhei1101/rule-inject/blob/develop/dev-docs.yaml) を dev-docs の設定のバージョン 3 の書式に移し、rule-inject の既存の文書全体を `documents[]` の行に載せて、dev-docs の検索でタグ・説明・関連から引けるようにする。

- 設定のバージョンを 1 から 3 へ上げる。dev-docs の `dev-docs migrate --source dev-docs.yaml --plan` の手順を当て、当てられない分は手で移す（[利用者の依頼](https://github.com/shuhei1101/rule-inject/issues/70#issuecomment-6517091151)）
- `check_project`（`path` は配信元のフォルダ）の違反を 0 件にする。今の違反は `documents[0].type` が知らないキー・`documents[0].schema` が無い・`documents[0].metadata.tags` の型が違う（期待: string）の 3 件
- 書式は dev-docs の [設定](https://github.com/shuhei1101/dev-docs/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E8%A8%AD%E5%AE%9A.md) と [文書のメタデータ](https://github.com/shuhei1101/dev-docs/blob/develop/docs/%E3%81%AF%E3%81%98%E3%82%81%E3%81%AB/%E3%82%B3%E3%82%A2%E3%82%B3%E3%83%B3%E3%82%BB%E3%83%97%E3%83%88/%E6%96%87%E6%9B%B8%E3%81%AE%E3%83%A1%E3%82%BF%E3%83%87%E3%83%BC%E3%82%BF.md) に従う

YAML の設計書（[dev/設計書/](https://github.com/shuhei1101/rule-inject/blob/develop/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/) の下と、各フォルダの `index.yaml`）:

- 種類ごとに 1 行を置き、`schema` に [dev/テンプレート/](https://github.com/shuhei1101/rule-inject/blob/develop/dev/%E3%83%86%E3%83%B3%E3%83%97%E3%83%AC%E3%83%BC%E3%83%88/) のその種類の Schema を指す
- `metadata` は既存の列の対応（`name: title` など）だけにし、設計書へ列を追加しない（配布されたテンプレートの Schema に触れるため）

Markdown・ソースコード・テスト:

- 管理用の YAML（`files.yaml`）に 1 ファイル 1 行で載せ、`records: files`・`body_file: path` の行で配信する。スキーマは dev-docs の `templates/files.schema.yaml` を `schemas/files.schema.yaml` にコピーして指す
- 載せるのは、dev-docs の除外の条件（生成物・ロック・バイナリ・ベンダーのコード・再エクスポートや空の `__init__`）に当たらない `docs/`・`src/`・`tests/`・`hooks/` のファイルと、`README.md`・`CLAUDE.md`
- `index.yaml` から生成した `README.md` は載せない（目次の正本は `index.yaml`）
- 行は `dev-docs files` で求め、各行に `name`・`description`（「何を受け持つか」と「どんなときに読むか」の 1 文）・`tags`（`topic`・`tool` だけ）・`related`（コードの側にだけ `implements`・`tests`・`see_also`）を書く。設計書と 1 対 1 の部分のコードには `implements` を必ず書く
- 判定フローチャートのページ（[#72](https://github.com/shuhei1101/rule-inject/pull/72) で `type: markdown` の行に載せた）は `files.yaml` の行へ移し、付けていたタグを `topic:` へ寄せて残す（`scope:判定フローチャート` は `topic:判定フローチャート` にする）

タグはマスターを持たずに付ける。
使われているタグを `search_docs` の `group_by: tags`（横断は `source: *`）で引き、同じ意味のタグがあれば使い回す（D-169）。

終わりの条件:

- `check_project` の違反が 0 件で、利用者の端末の dev-docs の配信に rule-inject が戻る
- `search_docs` で、付けたタグからページ・ソースコード・テストを引け、設計書へは `related`・`trace_related` で辿れる

`files.yaml` は範囲のフォルダごとに置く（`docs/files.yaml`・`src/files.yaml`・`hooks/files.yaml`・`tests/files.yaml`）。
直下の `README.md`・`CLAUDE.md` は `docs/files.yaml` に `../README.md`・`../CLAUDE.md` で載せる。
直下に `files.yaml` を置くと、dev-docs のずれの検出がリポジトリの全てのファイルを「索引に無いファイル」として数えるため。

YAML の設計書はタグの列を持たないため、この PR では設計書にタグを付けない（[確認事項](https://github.com/shuhei1101/rule-inject/pull/79#discussion_r4423180689)）。
設計書へは、タグで当てたコード・テストの `related` か、設計書を起点にした `trace_related` で辿る。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| Markdown の文書を YAML へ変換する | `dev/` の Markdown は全て `index.yaml` から生成した README で、手で書いた Markdown は `docs/` の利用者向けのページ・`README.md`・`CLAUDE.md` だけ。D-103 で Markdown のまま残す種類に当たる | 予定なし |
| YAML の設計書へ `description`・`tags` の列を追加する | 配布されたテンプレート（`dev/テンプレート/*.schema.yaml`）の Schema の変更になり、AI Monitor の配布物の範囲 | [shuhei1101/ai-monitor#3082](https://github.com/shuhei1101/ai-monitor/issues/3082)（`tags` の列。`description` の列は含まない） |
| 端末の設定（`~/.config/dev-docs/settings.yaml`）の rule-inject の配信元の行 | 利用者が develop の worktree を配信元として登録済みで、変えない | 予定なし |
| `dev/pr/` の PR ドキュメントを載せる | A-19 で文書の量から外している | 予定なし |
