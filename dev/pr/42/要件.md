## 要望

| Issue | 終わりの条件 |

| [#37](https://github.com/shuhei1101/rule-inject/issues/37) | `dev/設計書/インターフェース定義/プラグイン/ルール案内.py.yaml` の異常系「ルールの場所の変数参照を展開できない・止めずに理由を載せる」で、通常のエントリが入力のパスに当たり（`paths: ["**/*.py"]`・`on: [read]`）、期待値に「`additionalContext` に通常のエントリのルールの場所が載っている」がある |
| [#40](https://github.com/shuhei1101/rule-inject/issues/40) | `dev/設計書/設定/プラグイン.yaml` の `rules[].rule` の `missing` と `docs/リファレンス/索引の書式.md` の `### rule` の記述が、`src/rule_inject/features/index/_yaml.py` の `_read_entry` の扱いと食い違わない |

- #37: 異常系「ルールの場所の変数参照を展開できない・止めずに理由を載せる」を、異常系「読めない正規表現・止めずに理由を載せる」と同じ形にする
  - 通常のエントリを `paths: ["**/*.py"]`・`on: [read]` にして入力の `.py` のパスに当て、`notes` を、読み飛ばしの後もその案内が出ることを見る記述に修正する
  - 期待値に「`additionalContext` に通常のエントリのルールの場所が載っている」を追加する
  - 結合テスト `tests/integration/plugin/test_rule_guide.py` の `test_error_when_rule_variable_unset` の索引と検証を同じに修正する
- #40: `rule` の無いエントリの扱いを、実装（行番号つきの ValueError で、その索引を読まない）に合わせて記述する
  - `rules[].rule` の `missing` は、`rule` の無いエントリがあるとその索引を読まず、索引が読めないときと同じく索引の場所と理由をコンテキストへ載せる。設定されていない環境変数の `!{名前}` が残ったときは、今の記述のままそのエントリだけを読み飛ばす
  - `docs/リファレンス/索引の書式.md` の `### rule` も同じ扱いに修正する
  - 実装へ合わせる根拠: モジュール構成「索引」の `parse_index` は `rule` の無いエントリを行番号つきの ValueError にすると書いており（単体テスト `test_parse_index_when_rule_missing`）、実装と一致する。食い違うのは設定の設計書と公開ドキュメントだけ。[#38](https://github.com/shuhei1101/rule-inject/pull/38) で `read_by[].tools` の `missing` を同じ方向（その索引を読まない）で修正している
