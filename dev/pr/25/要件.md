# 要件

## 要望

書く操作が通ることを確かめる E2E のケースで、`--allowedTools` に Write と Edit の両方を渡す。
検証（`permission_denials` が空・対象のファイルに中身が書かれている）は変えない。

対象のケースは次のとおり。

- `tests/e2e/単一ユースケース/test_receive_unread_rule_guidance.py` の `test_normal_when_already_read`・`test_error_when_index_unreadable`・`test_error_when_rule_variable_unset`
- `tests/e2e/複合ユースケース/test_read_rule_then_touch_file.py` の `test_normal`・`test_normal_when_read_by_bash`・`test_normal_when_after_compact`

Write が止められることだけを確かめるケース（`test_normal_when_blocked`・`test_normal_when_guidance_too_long`・`test_normal_when_default_index`・`test_normal_when_rule_has_variable`）は変えない。

シナリオの設計書には、対象のシナリオのセットアップへ、許可するツール（Write と Edit）を書き足す。

## 更新ドキュメント

なし

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 検証を「`permission_denials` に Write が無い」へ置き換える直し方 | Edit が止められたまま対象のファイルに中身が書かれず、シナリオの期待値（対象のファイルに中身が書かれている）を確かめられない | 予定なし |
| 作業の決まり（空で作ってから Edit で書く）の文面の変更 | プラグインの挙動は設計どおりで、fail の原因はテストが渡す許可の不足 | 予定なし |
