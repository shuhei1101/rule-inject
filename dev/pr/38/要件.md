# 要件

## 要望

- 索引のエントリに `read_by` を足し、そのルールを既読にする MCP ツールの呼び出しを書ける
  - `read_by` の要素ごとに、MCP ツールの完全名のパターンのリスト `tools` と、引数のパターン `args` を持つ。要素のどれか 1 つに当たれば既読にする
  - パターンは案内の当て方の `tools`・`args` と同じく glob か `re:` の正規表現で書き、引数の照合の規則（ドット区切りのキー・配列は要素ごと・文字列以外のスカラーは JSON の表記）は `args` と同じにする
  - 書いた全ての引数のキーの値が当たるときだけ当てる
  - 案内の当て方の `tools`・`args` に当たっただけでは既読にしない
- MCP ツールの呼び出しが終わった後（PostToolUse）に、当たったエントリのルールの場所を、そのセッションの既読にする
  - 既読にした後は、そのルールの案内で操作を止めない（Read・`read_rules` で読んだときと同じ）
  - このプラグイン自身の MCP ツール（`mcp__plugin_rule-inject_rule-inject__*`）は、今までどおり `read_rules` の処理で既読にする
  - 既読を書けないときは、今の既読の記録と同じく既読にできなかった場所と理由をコンテキストへ載せ、操作は止めない
  - フックは今の打ち切り（1 秒）の中で終える
- 既読の履歴（いつ・どのセッションで・どの読み方で・どのルールを読んだか）を、ほかの仕組み（関連する文書の推薦など）が読める形で残す
  - Read・Bash・`read_rules`・MCP ツールのどの読み方で既読にしたときも履歴に残す
  - 今の既読の記録とは別に、セッションごとの履歴のファイル（1 行 = 1 回の既読の JSON Lines。時刻・セッション・読み方・ツール名・ルールの場所）へ追記する
  - 読み方は `read`（Read）・`bash`（Bash の読むコマンド）・`read_rules`・`mcp`（`read_by` に当たった MCP ツール）のどれか
  - 圧縮では捨てず、終わったセッションの記録の掃除と同じ保持期間で消す
  - 履歴にだけ書けないときは、既読にはして操作を止めない。フックは書けなかった旨をコンテキストへ載せ、`read_rules` は本文を返して書けなかった旨を応答に載せる（既読の記録に書けないときの `read_rules` は今のままエラーを返す）

| 項目 | 理由 | 対応予定 |

| knowledge の `dev/コーディング規約/dev/ルール索引への登録.md` に、既読にする MCP ツールと引数の書き方を追加する | knowledge リポジトリの規約で、このリポジトリの変更を前提にする後続 | [shuhei1101/knowledge#45](https://github.com/shuhei1101/knowledge/issues/45) |

| ルールのバージョンを見て、古いバージョンを既読にしたときに差分だけを案内する（A-9 の 5 番） | Issue の要望に含まれない | 予定なし |
