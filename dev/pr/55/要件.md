# 要件

## 要望

knowledge の規約を正として、このリポジトリの文書・表示する文言・コードのコメントの語を修正する。

- 正にする規約（[shuhei1101/knowledge#34](https://github.com/shuhei1101/knowledge/issues/34) で入った）
  - 規約『文章の書き方』の `## 語の選び方`（原則・ドキュメントの語の対応表）
  - 判定フローチャート『語の選び方』
  - コーディング規約『ui/入力と文言』の `### 語と書式`・`### 操作の語`
- 文章でない所（見出し・表の列名・項目名・論理名・設計書の `title`・`summary`・`name`・`index.yaml` の `summary`）は、対応表の語にする。対応表に無い語は判定フローチャート『語の選び方』で決める
- 一字の語と比喩（版・節・題・印・口・形・段・写し・問い・答え）は、文章の中でも対応表の語にする
- 文章の中の動詞（送る・足す・消す・直す）は、「する」を付けた対応表の語（送信する・追加する・削除する・修正する）を既定にする。冗長な言い回し（することができる・を行う）と話し言葉を修正する
- 長音は語末の -er / -or / -ar / -y に付ける（ユーザー・サーバー・メモリー）
- フックがコンテキストへ返す文言（案内文・失敗の知らせ・索引と設定ファイルの YAML のエラーメッセージ・`hooks/run.py` の Python のバージョンの知らせ）は、規約『入力と文言』の語と書式に合わせる。エラーは「〜できませんでした」「〜がありません」で終え、原因と対処を入れる
- コードのコメント・docstring・`hooks/hooks.json` の `_description` も同じ規約で修正する（判定フローチャート『語の選び方』がコードのコメントを対象に含め、モジュール構成の設計書と同じものを同じ語で呼ぶため）
- コードの識別子・Enum の値・定数の名前は英語のまま変えない
- ファイル名・見出し・設計書の項目名を変えたときは、そのファイル・見出し・項目へのリンクと参照も修正する
- 修正の前後に `集計/reposcan.py`（`/mnt/c/Users/shuhe/repo/knowledge/tmp/ui、ドキュメントの文章ベストプラクティス/集計/reposcan.py`）で件数を数え、前後の件数を PR ドキュメントに記載する。`reposcan.py` は `.py` を数えないため、同じ語の正規表現で `src/`・`hooks/`・`tests/` も数えて併記する
