# 要件

## 要望

- 読むコマンドの引数のうち、引用符の外の glob（`*` `?` `[...]`）を、その時点の基準（`cwd` をそれまでの `cd` で動かしたフォルダ）から展開し、当たった実在するファイルを読む対象にする
  - 当たるファイルが無い glob は、今と同じく実在しないパスとして捨てる
  - 引用符の中の glob（`grep "a*b" x.md` のパターン）は展開しない
- `for {変数} in {語の並び}; do … {読むコマンド} "${変数}" …; done` の形で、`do` から `done` までの読むコマンドが `for` の変数（`$f` / `"$f"` / `${f}` / `"${f}"`）を引数に取るとき、`for` の語の並びを読む対象にする
  - 語の並びの glob は、上と同じ規則で展開する
  - 読むコマンドが変数を引数に取らない `for`（`for f in a b; do echo "$f"; done`）は、語の並びを読む対象にしない
- 既読の記録（`FULL_READ_COMMANDS`）も同じ取り出しを使い、`cat src/tasks/*.py` と、`do` の中の全体を読むコマンドが変数を引数に取る `for` で読んだルールのファイルを既読にする
  - glob の展開と `for` の語の並びは、どちらもファイル全体を出すコマンドへ渡した引数で、[#47](https://github.com/shuhei1101/rule-inject/pull/47) の「全文を読んだときだけ既読にする」と食い違わない
- 確かめ方: Issue の `for` のコマンドと `cat src/tasks/*.py` で、当たるルールの案内が出ること（ルール案内）と既読になること（既読の記録）を単体テストで確かめる

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `while read` / `xargs` / `find -exec` / コマンド置換（`$(...)`）で読むファイル | 要望に含まれない。読むファイルが実行の結果で決まり、コマンドの文字列だけからは取り出せない | 予定なし |
| 入れ子の `for`・`do` の中の変数を加工した引数（`"$dir/$f"`） | 要望に含まれない。`for` の変数をそのまま引数に取る形だけで Issue の事象は直る。含めるかはレビューで確定する | 予定なし |
| ブレース展開（`{a,b}.py`）と `**` のフォルダをまたぐ展開 | 要望に含まれない。Bash の既定（`globstar` なし）では `**` は `*` と同じで、同じ規則で展開する | 予定なし |
| エージェントのセッションのフックが、無いファイル `/mnt/c/Users/shuhe/repo/rule-inject/rules.yaml` の索引を読もうとして毎回「索引を読めませんでした」を出す | ai-monitor がセッションへ渡す環境変数の不具合で、今回の要望に含まれない | [shuhei1101/ai-monitor#3027](https://github.com/shuhei1101/ai-monitor/issues/3027) |
