## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 型検査の追加 | `pyproject.toml` の `dev` グループに mypy を追加し、`[tool.mypy]` に設定を置く。既定の厳しさで `uv run mypy .` を `src` と `tests` に流す | `tests` の `conftest.py` の同名モジュールの重複は、mypy の設定で解消する |
| 依存の向きの検査の追加 | `pyproject.toml` の `dev` グループに import-linter を追加し、`[tool.importlinter]` に契約を置く | 契約は `hooks`・`server` → `features` → `shared` のレイヤーと、`features` の下の機能どうしの独立 |
| 型の誤りの修正（hooks） | `session_id` の形式を確かめた後の値を `str` として扱えるよう、型の絞り込みで修正する。`rule_guide` は判定の結果を bool の変数に入れず、判定で絞り込んだ `str \| None` の変数を作り、分岐と引数にその変数を使う | フックの入出力・振る舞いは変えない |
| 型の誤りの修正（shared・features/index） | 設定の値と索引の YAML の値を、渡す前に型で絞り込む | 読み取りの結果は変えない |
| 型の誤りの修正（features/record） | `_history_entry` で、確かめた値を変数ごとに `isinstance` で絞り込んでから `HistoryEntry` へ渡す | 読み取りの結果は変えない |
| 型の誤りの修正（tests） | テストの検証内容を変えずに型の誤りを修正する。`func-returns-value` は戻り値を受けずに呼ぶ形にする。`dict \| None` と `CallToolResult.content` の要素は、添字・`.text` の前に `assert` か `isinstance` で絞り込む。`paths` はモジュールを直接 import する | 検証する値・ケースは変えない |
| テスト実行方法 | `layers[lint]` の説明・前提・全件実行に mypy と import-linter を追加する | 配布元の Schema の `lint` 層の例に合わせる |
