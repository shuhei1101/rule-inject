## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定のパス | `RULE_INJECT_CONFIG` の値、無ければ `XDG_CONFIG_HOME`（無いか空なら `~/.config`）の下の `rule-inject/settings.yaml` を読む | 指したファイルが無いときは今どおり誤り。既定のパスのファイルが無いときは設定なしで動く |
| 状態の置き場所 | `RULE_INJECT_STATE_DIR` を `global.state_dir` より優先する | 既定のログのフォルダは、この値があればその下の `logs`。空の値は無いものとして扱う |
| `global-setup` | dev-docs の `global-setup` を元に、A-44 の流れをスキルにする。`AskUserQuestion` は既定値を推奨の選択肢にする | サーバーの起動は規約『ローカルサーバーの立て方』の systemd のユーザーのユニットにする。クローンの場所とサービス名（既定 `rule-inject`）は引数か質問で受ける。確認への回答は引数の `--yes`・`--no` でも指定でき、待ち受けているサーバーは起動し直さない |
| `setup` | リポジトリの `rules.yaml` を索引に登録し、索引のチェックの結果を示す | 端末の設定が無ければ `global-setup` を案内して止まる |
| `env` への記載 | 設定のパスが既定と違うときだけ、`${CLAUDE_CONFIG_DIR:-~/.claude}/settings.json` の `env` に書く | `env` のほかのキーと、ファイルのほかの内容は変えない |
| `version` と移し替え | 設定ファイルの `version` を読み、バージョンごとの移し替えの手順を持つ | 手順の示し方と当て方は `global-setup` が呼ぶ |
| 旧い登録 | `global-setup` が `claude mcp` でユーザースコープの `rule-inject` を調べ、確認してから削除する | - |
| テストの隔離 | 単体テストも `XDG_CONFIG_HOME` を一時フォルダへ向け、利用者の設定を読まない | 結合・E2E は隔離済み |
