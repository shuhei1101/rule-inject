# 要件

## 要望

- 端末の設定
  - `RULE_INJECT_CONFIG` が無いときは `${XDG_CONFIG_HOME:-~/.config}/rule-inject/settings.yaml` を読む
  - 既定のパスのファイルが無いときは、今どおり設定なし（全てのキーを既定値）で動く。既定のパスのファイルがあって読めないときは、`RULE_INJECT_CONFIG` で指したときと同じ誤りとして扱う
- 上書きの環境変数
  - `RULE_INJECT_CONFIG`（設定のパス）・`RULE_INJECT_PORT`（ポート）・`RULE_INJECT_STATE_DIR`（状態の置き場所）に統一する
  - `RULE_INJECT_STATE_DIR` を新設する。状態の既定の置き場所は今どおり `${XDG_STATE_HOME:-~/.local/state}/rule-inject`
- MCP の配布
  - プラグインのルートの `.mcp.json` に `http://127.0.0.1:${RULE_INJECT_PORT:-8783}/mcp` を記載して配る
  - `claude mcp add` のセットアップの手順を廃止する
- セットアップのスキル
  - `global-setup`: A-44 の流れ（設定のパスの決定 → 移し替えか雛形からの作成 → パスが既定と違えば `env` への記載 → サーバーの起動と `tools/list` の確認 → フックの確認 → 結果の提示）を端末ごとに実行する
  - `setup`: リポジトリの `rules.yaml` を索引に登録する。リポジトリの直下の `rules.yaml` は既定で読むため書き込まず、索引のチェックだけを実行する。別の場所の索引だけ `projects[]` に記載する
- `global.server_port` を廃止し、ポートを `RULE_INJECT_PORT` だけで指す。残っている設定は `global-setup` が検出して `env` へ移す
- 設定ファイルに `version` を持たせ、バージョンごとの移し替えの手順を持つ（規約『YAML』の `config-file-05`〜`07`）
- `claude mcp add -s user rule-inject` の旧い登録は、`global-setup` が検出し、利用者に確認してから削除する
