# 要件

## 要望

[#52](https://github.com/shuhei1101/rule-inject/pull/52) の反映作業「利用者の設定ファイルへの移行」のスクリプトを、`~/.config/rule-inject/settings.yaml` が既にある端末でも完了できるようにする（Issue の対策の候補の 1 つ目）。

| スクリプト | settings.yaml が既にあるときの振る舞い |
| --- | --- |
| `実行.py` | settings.yaml を書き換えない。`env` の旧キーの値が settings.yaml の `global` の対応するキーに入っていれば（`indexes` は env の要素が全て含まれていれば）、`env` の旧キーを削除するだけにする。入っていない値があれば、前提確認で、入っていないキーと値を示して止まる |
| `確認.py` | settings.yaml の全文の一致ではなく、バックアップの `env` の旧キーの値が settings.yaml の `global` に入っているかで判定する。バックアップがある settings.json は、`env` に `RULE_INJECT_` のキーが無くても判定の対象にする。バックアップの `env` にも今の `env` にも `RULE_INJECT_CONFIG` が無い settings.json は、`RULE_INJECT_CONFIG` が無いことを `ok` にする |
| `切り戻し.py` | 実行で作っていない settings.yaml は削除しない（`settings.json` だけをバックアップから戻す）。今の settings.json の `env` に `RULE_INJECT_CONFIG` があり、そのバックアップには無いときだけ、実行で作った settings.yaml として削除する |

- settings.yaml が無い端末の振る舞いは変えない
- settings.yaml が既にあるときは `RULE_INJECT_CONFIG` を `env` に追加しない。既定のパスの settings.yaml はプラグインが `env` 無しで参照し、global-setup も既定と違うパスのときだけ記載する
- [#52](https://github.com/shuhei1101/rule-inject/pull/52) の `反映作業/index.yaml` の `説明`・`確認方法` を、settings.yaml が既にある場合を含む内容に書き換える
- 書き換えたスクリプトは `--dry-run` でこの端末で実行し、出力を `反映作業/利用者の設定ファイルへの移行/dry-run.log` に配置し直す。この端末の想定の出力は、前提確認が `ok`、settings.yaml の作成が `skipped`、`env` に `RULE_INJECT_INDEXES_USER` を持つ `settings.json` ごとの書き換えが `changed`
- 反映作業の実行は、この PR を含む release が master へ入った後に、[#52](https://github.com/shuhei1101/rule-inject/pull/52) の反映作業として tester が実行する（この PR は反映作業を持たない）
