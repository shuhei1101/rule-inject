# 常駐の MCP サーバーの索引のチェックに paths の当たらないエントリの検出を追加し、既読の記録を確認・削除するツールを追加する

## 概要

利用者が、常駐の MCP サーバーの索引のチェックで `paths` がプロジェクトのどのファイルにも当たらないエントリを見つけられ、セッションごとの既読のルールと読んだ方法の確認と、既読の記録の削除（ルールを未読に戻す）をツールで行えるようになる。

## 背景

[Issue #68](https://github.com/shuhei1101/rule-inject/issues/68) は [#64](https://github.com/shuhei1101/rule-inject/issues/64) と [#65](https://github.com/shuhei1101/rule-inject/issues/65) を束ねた Issue。
どちらも [#58](https://github.com/shuhei1101/rule-inject/issues/58) の「追加の候補」から出たもので、常駐の MCP サーバーを追加した [PR #59](https://github.com/shuhei1101/rule-inject/pull/59) の `## スコープ外` に置いた。
#59 の `check_indexes` が返すのは、フックが読めない理由・JSON Schema への違反・`rule` の場所にファイルが無いエントリ・読み飛ばすエントリだけで、案内が出ることのないエントリは見つけられない。
既読の記録は、フックが書き、圧縮の前と保持期間の後に削除するだけで、サーバーは既読の記録を読まない。
