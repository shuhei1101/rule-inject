### #64: paths の当たらないエントリの検出

- `check_indexes` に問題の種類を 1 つ追加し、効いているエントリのうち `paths` を持ち、`project_dir` の下のどのファイルにも当たらないエントリを、索引ごとに位置・バージョン・`rule` つきで返す
  - 当たるかは、フックと同じ照合（`paths` と `exclude`。`on` の操作の種別は問わない）で、ファイルの絶対パスに当てて決める
  - 無効のエントリ・読み飛ばすエントリ・`paths` を持たないエントリ（`tools` だけ）は確かめない
  - 既定では、プロジェクトの索引（当たった `projects[].indexes` と、プロジェクトの既定の置き場所の索引）だけを確かめ、`global.indexes`・ユーザーの既定の索引は確かめない（複数のプロジェクトで共有するエントリは、そのプロジェクトのファイルに当たらないのが正しい状態のため）
  - `check_indexes` に、ユーザー全体の索引も確かめるかの引数を追加する。オンにすると、ユーザー全体の索引の `paths` の当たらないエントリを、プロジェクトの索引の分とは分けて返し、`problem_count` に数えない
  - フックが読めない索引は、今どおりその理由だけを返す
- 既存の問題の種類（`hook_error`・`violation`・`missing_rule`・`skipped_entry`）の判定と応答は変えない
- 編集のツール（`write_index_entry`・`delete_index_entry`）の書き込み前の検証には、この問題の種類を含めない（書く索引のエントリが、まだ作っていないファイルを指すことがあるため）
- `project_dir` の下を `.git` だけ除いて全て辿り（`.gitignore` で除いたファイルも含む）、辿る時間の上限を超えたら辿るのをやめ、検出を終えられなかったことを応答に載せる（上限の値は非機能要件『プロジェクトのファイルを辿る時間』）

### #65: 既読の記録の確認と削除

- 既読の記録の確認のツール: `session_id` を受け、そのセッションの既読のルールの場所ごとに、今の本文が既読にした時点と同じか（同じでなければ案内では未読として扱う）と、既読の履歴（`.history.jsonl`）に残る読んだ方法（`method`・`tool`・`time`）を返す
  - `session_id` を省くと、記録フォルダに既読の記録があるセッションの一覧を、最終更新の時刻つきで新しい順に返す（サーバーは Claude Code のセッションの ID を受け取らないため）
- 既読の記録の削除のツール: `session_id` を受け、そのセッションの既読の記録と案内済みの記録（`.guided.txt`）をファイルごと削除し、次のフックの呼び出しから止める案内と止めない案内を初めから出させる
  - 圧縮の前の削除と同じ単位にする（既読の記録は複数のフックが追記だけで書くため、行を取り除いて書き直さない）
  - 記録の無いセッションはエラーにせず、未読に戻したルールが無いことを返す
- 両ツールとも、記録ファイル名に使えない形式の `session_id` はツールのエラーにする
- 既読の履歴は削除しない（圧縮で既読の記録を削除するときも残す、ほかの仕組みが読む閲覧の記録のため）
- 記録フォルダは、フックと同じ設定（`global.state_dir`、既定 `${XDG_STATE_HOME:-~/.local/state}/rule-inject`）から決める
- フックの動作と、既読の記録・案内済みの記録・既読の履歴のファイルの書式は変えない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `exclude` がどのファイルにも当たらないパターンの検出 | 要望は `paths` の当たらないエントリの検出で、`exclude` の不要なパターンは案内の有無を変えない | 予定なし |
| `tools` がどの MCP のツールにも当たらないエントリの検出 | 呼び出しうるツールの一覧をサーバーが持たない | 予定なし |
| 既読の記録への行の書き足し（ツールでルールを既読にする） | 要望は確認と削除で、既読はフックだけで付けると [#44](https://github.com/shuhei1101/rule-inject/pull/44) で決めている | 予定なし |
