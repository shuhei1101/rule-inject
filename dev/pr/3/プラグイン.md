## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 案内（`PreToolUse`） | Read / Edit / Write / Bash / MCP のツールの呼び出しで、対象のパス・ツール名・操作の種別に当たる未読のルールがあれば操作を止め、ルールの場所を案内する | パス・ツール名には当たるが操作の種別には当たらないときは止めずに案内し、案内文を止めるときと分ける |
| セッションの受け渡し（`PreToolUse`） | MCP サーバーのツールの呼び出しで、`updatedInput` に元の引数をすべて写して `session_id` を足す | PoC 検証で確かめる |
| 既読の記録（`PostToolUse`） | ルールの本文を取りに行った場所を、そのセッションの既読として記録する | |
| 本文の取得（MCP） | ルールの場所か対象のパスを受け、当たるルールの本文を返してそのセッションの既読として記録する | 場所はローカルのパスと URL |
| 既読の記録の破棄（`PreCompact`） | そのセッションの既読の記録を捨てる | |
| 作業の決まり（`SessionStart`） | 新しいファイルは空で作ってから中身を書く決まりをコンテキストへ載せる | |
| 索引の読み込み | ユーザー用・プロジェクト用の環境変数からカンマ区切りの索引を読み、両方のエントリを合わせて当てる | 環境変数の名前と YAML の書式は設計で確定 |
| 既読の記録の置き場所 | セッションごとのファイルを rule-inject の名前の状態フォルダに置き、フックと MCP サーバーが同じファイルを読み書きする | 候補 `~/.local/state/rule-inject/`。設計で確定 |
| 依存 | フックは Python の標準ライブラリだけで書く。MCP サーバーは uv のプロジェクトとして `.mcp.json` から `uv run` で起動する | |
| 動作環境 | Linux / WSL の端末で動かし、常駐するサーバーは持たない | |
| 持ち込まないもの | 特定の開発基盤に依存する処理と、特定の開発基盤や作者の環境を思わせる語を持たない | README・コード・案内文が対象 |
