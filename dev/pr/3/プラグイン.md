## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 案内（`PreToolUse`） | Read / Edit / Write / Bash / MCP のツールの呼び出しで、対象のパス・ツール名・操作の種別に当たる未読のルールがあれば操作を止め、ルールの場所を案内する | パス・ツール名には当たるが操作の種別には当たらないときは止めずに案内し、案内文を止めるときと分ける |
| セッションの受け渡し（`PreToolUse`） | MCP サーバーのツールの呼び出しで、`updatedInput` に元の引数をすべて写して `session_id` を足す | PoC 検証で確かめる |
| 既読の記録（`PostToolUse`） | ルールの本文を取りに行った場所を、そのセッションの既読として記録する | |
| 本文の取得（MCP） | ルールの場所か対象のパスを受け、当たるルールの本文を返してそのセッションの既読として記録する | 場所はローカルのパスと URL |
| 既読の記録の破棄（`PreCompact`） | そのセッションの既読の記録を捨てる | |
| 作業の決まり（`SessionStart`） | 新しいファイルは空で作ってから中身を書く決まりをコンテキストへ載せる | |
| 索引の読み込み | ユーザー用・プロジェクト用の環境変数からカンマ区切りの索引を読み、両方のエントリを合わせて当てる | 環境変数の名前と YAML の書式は設計で確定 |
| 既読の記録の置き場所 | セッションごとのファイルを rule-inject の名前の状態フォルダに置き、フックと MCP サーバーが同じファイルを読み書きする | 候補 `~/.local/state/rule-inject/`。設計で確定 |
| 依存 | フックは Python の標準ライブラリだけで書く。MCP サーバーは uv のプロジェクトとして `.mcp.json` から `uv run` で起動する | |
| 動作環境 | Linux / WSL の端末で動かし、常駐するサーバーは持たない | |
| 持ち込まないもの | 特定の開発基盤に依存する処理と、特定の開発基盤や作者の環境を思わせる語を持たない | README・コード・案内文が対象 |

## PoC 結果

| 検証構成 | 成功条件 | 結果 | PoC PR | 補足 |
| --- | --- | --- | --- | --- |
| 回 1〜3: `updatedInput` だけ（`permissionDecision` なし）+ `--allowedTools` で先に許可 | ツールが受け取った `session_id` がフックの入力の `session_id` と 3 回とも一致する | ✅ 3/3 一致 | [#4](https://github.com/shuhei1101/rule-inject/pull/4)（closed） | 回 2 でモデルが渡した `model-supplied` もフックの値で上書きされた |
| 回 1〜3 | ツールが受け取った `location` がモデルが渡した値と同じ | ✅ 3/3 一致 | [#4](https://github.com/shuhei1101/rule-inject/pull/4)（closed） | - |
| 回 4: `permissionDecision: allow` + `updatedInput`、先に許可しない | 注入され、先に許可しなくても自動で許可される | ✅ 注入・自動許可 | [#4](https://github.com/shuhei1101/rule-inject/pull/4)（closed） | 許可の確認が黙って飛ぶため、本番では使わない |
| 回 5: `permissionDecision: ask` + `updatedInput`、先に許可しない | ツールが呼ばれずに拒否される | ✅ 拒否 | [#4](https://github.com/shuhei1101/rule-inject/pull/4)（closed） | 拒否の文面はフックの `permissionDecisionReason`（`PoC: ask`）で、`permission_denials` の入力には注入後の `session_id` が載っていた |
| `.mcp.json` の `uv run` での起動 | プラグインの MCP サーバーが起動し、ツールがモデルの一覧に出る | ✅ 起動 | [#4](https://github.com/shuhei1101/rule-inject/pull/4)（closed） | `mcp` 2.x では `FastMCP` が `MCPServer`（`mcp.server.mcpserver`）に改名されており、1 回目は起動に失敗した |

結論は成立で、`permissionDecision` を付けずに `updatedInput` だけを返す注入を採用する。
参考の `CLAUDE_CODE_SESSION_ID`（MCP サーバーのプロセスの環境変数）は、5 回ともフックの `session_id` と一致した（`/clear` は起こしていない）。
MCP サーバーが接続に失敗すると、Claude Code はその失敗を 15 分覚えて接続を試さない。サーバーを直しても、`.mcp.json` を書き換えるまで再接続されなかった。

最小再現の核心は、フックが `tool_input` を写して `session_id` を足した `updatedInput` だけを返す部分（`poc/rule-inject-poc/hooks/inject.py`）。

```python
data = json.load(sys.stdin)
updated = {**data.get("tool_input", {}), "session_id": data["session_id"]}
output = {"hookEventName": "PreToolUse", "updatedInput": updated}
print(json.dumps({"hookSpecificOutput": output}))
```

PR の diff の見どころは次の 2 つ。

- `poc/results/poc.log.jsonl`: フックとツールが受け取った値の突き合わせ
- `poc/results/run5.json`: `permission_denials` と拒否の文面
