# 要件

## 要望

Claude Code のプラグイン 1 つ（フック + stdio の MCP サーバー）として、次を満たす。

- `PreToolUse` フックが、操作の対象のパス（またはツール名）と操作の種別（読む / 書く / MCP）に当たる未読のルールを見つけたら、操作を止めてルールの場所を案内する
- `PostToolUse` フックが、ルールの本文を取りに行った場所をそのセッションの既読として記録する
- MCP サーバーのツールが、ルールの場所か対象のパスを受け、当たるルールの本文を返してそのセッションの既読として記録する。場所はローカルのパスと URL の両方を扱う
- MCP のツールに当てる `PreToolUse` フックが、`hookSpecificOutput.updatedInput` で元の引数をすべて写したうえで `session_id` を足す
- `PreCompact` フックが、そのセッションの既読の記録を捨てる
- `SessionStart` フックが、新しいファイルは空で作ってから中身を書くという作業の決まりをコンテキストへ載せる
- 索引（YAML）はユーザー用とプロジェクト用の 2 つの環境変数で指し、どちらもカンマ区切りで複数並べられる。エントリはルールの場所・当てるパスの glob・当てるツール名・当てる操作の種別を持つ
- 既読の記録はセッションごとのファイルに置き、フックと MCP サーバーが同じファイルを読み書きする
- フックは Python の標準ライブラリだけで書き、MCP サーバーは uv のプロジェクトとして `.mcp.json` から `uv run` で起動する。動かす場所は Linux / WSL の端末で、常駐するサーバーは持たない
- 特定の開発基盤に依存する処理（監視対象のプロジェクトの解決、基盤に固有の変数参照の展開、GitHub の API の呼び出し）と、特定の開発基盤や作者の環境を思わせる語を持たない

環境変数の名前・索引の YAML の書式・既読の記録の置き場所・セットアップの手順は設計で確定する。

## 影響するユースケース

| 種別 | ユースケース | 影響 | 依存 |
| --- | --- | --- | --- |
| 複合ユースケース | Claude Code がルールを読んでからファイルを触る | 新規（案内 → 本文の取得 → 既読の記録 → 操作のやり直し） | |
| 単一ユースケース | Claude Code が未読のルールの案内を受ける | 新規（`PreToolUse` が当たる未読のルールで操作を止めて案内する） | Claude Code がルールを読んでからファイルを触る |
| 単一ユースケース | Claude Code がルールの本文を取得する | 新規（MCP のツールが本文を返して既読にする。`session_id` は `PreToolUse` が引数へ足す） | Claude Code がルールを読んでからファイルを触る |
| 単一ユースケース | Claude Code がルールを読んだことが記録される | 新規（`PostToolUse` が本文を取りに行った場所を既読にする） | Claude Code がルールを読んでからファイルを触る |
| 単一ユースケース | Claude Code の圧縮で既読の記録が捨てられる | 新規（`PreCompact` がそのセッションの既読の記録を捨てる） | Claude Code がルールを読んでからファイルを触る |
| 単一ユースケース | Claude Code がセッションの開始時に作業の決まりを受け取る | 新規（`SessionStart` が空で作ってから書く決まりを載せる） | Claude Code がルールを読んでからファイルを触る |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 同じルールに複数のエントリが当たったとき、案内と必須の判定をルールごとに 1 つへまとめる | 判断: 取り込む。後から入れると案内文と既読の判定の両方を作り直すことになるため。スコープに含めるかはレビューで確定する | レビューで確定 |
| 案内文を、操作を止めるときと止めずに案内するときで分ける | 判断: 取り込む。止めない案内に「やり直してください」が出ると操作が重複するため。スコープに含めるかはレビューで確定する | レビューで確定 |
| エントリに、当てる範囲から外すパスを書けるようにする | 判断: 取り込む。索引の書式を最初に決める今が、項目を足しても既存の索引を壊さない時点のため。スコープに含めるかはレビューで確定する | レビューで確定 |
| Bash（`cat` / `grep` など）で読んだときもルールの案内と既読の記録をする | 判断: 取り込む。取り込まないと `cat` で本文を読んでも既読にならず、書く操作が止まり続けるため。スコープに含めるかはレビューで確定する | レビューで確定 |
| MCP のツールの引数に説明を付け、ルールの場所と対象のパスを取り違えないようにする | 判断: 取り込む。引数の説明はインターフェース定義で書くため追加の工程が要らない。スコープに含めるかはレビューで確定する | レビューで確定 |
| macOS・Windows（WSL を使わない環境）での動作 | 構成方針で動かす場所を Linux / WSL に限っている | 予定なし |
