# 要件

## 要望

- 文書の MCP の結果に載った文書の場所で既読にする（D-124）
  - 結果への載せ方の決まりを rule-inject の公開ドキュメントに定める。markdown は文書ごとに `<document path="..." scope="...">` で包み、json は各項目に `path`・`scope` を持たせる。`scope` は `full`・`section`・`summary` のどれか
  - 既読の記録のフック（PostToolUse）が MCP のツールの `tool_response` から文書の場所と範囲を取り出し、索引のルールの場所と照合する。特定のサーバーの構成には依存しない
  - 決まりに従わない MCP のツールは、今の索引の `read_by` で既読にする
- 全文を読んだときだけ既読にする（D-125）
  - Read は `offset`・`limit` がファイル全体を覆うときだけ既読にする。一部だけを読んだときは既読にしない
  - MCP の結果は `scope` が `full` の文書だけを既読にする。`section`・`summary` は既読にしない
  - Bash の全体を読むコマンドの扱いは変えない
- ルールが変わったら未読に戻す（D-126）
  - 既読の記録に、既読にした時点のルールの本文のハッシュを場所と一緒に残す
  - ルール案内（PreToolUse）と検索結果の案内（PostToolUse）は、既読かを決める前に今の本文のハッシュと比べ、違えば未読として扱う
- rule-inject#44 での変更（案内の文面を Read で読む形にする、既読の記録の `read_rules` の分岐を消す、セッションIDの付与を消す）を前提にする

文書の MCP が返す場所は、Read・Bash と同じ規則（`~` の展開・`cwd` から解く・`..` を畳む。シンボリックリンクは辿らない）で絶対パスへ解き、索引のルールの場所と比べる（インターフェース定義『既読の記録』の制約「MCP の結果の文書」）。
Read が全体を覆ったかは、`tool_response.file` の `startLine` が 1 で `numLines` が `totalLines` と同じかで判定する（PoC で確かめた。インターフェース定義『既読の記録』の制約「Read の全体の判定」）。
