## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| MCP の結果の書式 | markdown は `<document path="{絶対パスか URL}" scope="{full / section / summary}">` で文書ごとに包む。json は結果の項目ごとに `path`・`scope` を持つ | 書式の正本は `docs/リファレンス/MCPの結果の書式.md` |
| MCP の結果からの既読 | `mcp__` のツールの `tool_response` から書式に従う文書を取り出し、`scope` が `full` で場所が索引のルールの場所に当たるものを既読にする | 書式に従う文書が無いツールは `read_by` で照合する |
| Read の全文の判定 | 読んだ範囲がファイルの先頭から末尾までを覆うときだけ既読にする | `tool_response.file` の `startLine` が 1 で `numLines` が `totalLines` と同じとき全体とする（`## PoC 結果`） |
| 本文のハッシュ | 既読にするときに、ルールのファイルの本文のハッシュを場所と一緒に既読の記録へ書く | ファイルの中身の SHA-256 を `sha256:{16 進数}` で、場所とタブで区切って 1 行に書く（ER 図「既読の記録」）。既読の履歴の `method` は MCP の結果の文書でも `mcp` のまま |
| 未読に戻す | ルール案内・検索結果の案内は、既読の記録の場所のハッシュと今の本文のハッシュが違えば未読として扱う。本文を読めないルールは今の扱い（未読）のまま | 記録ファイルは書き換えず、読み直したときに新しいハッシュの行を追記する |
| 既存の既読の記録 | ハッシュを持たない行は既読として扱わない | 記録はセッションごとの一時的なファイルで、読み直せば既読になる |

## PoC 結果

結論: 成立。
Read は `tool_response.file` の値で全体を読んだかを判定でき、MCP は `tool_response` の文字列から文書の場所と範囲を取り出せる。
上限を超えた MCP の結果とサイズの上限を超えた Read は、文書の場所が残らないか PostToolUse が呼ばれないため、既読にならない。

Claude Code 2.1.310 の `claude -p` で確かめた（[PoC PR #48](https://github.com/shuhei1101/rule-inject/pull/48)、[a897c30](https://github.com/shuhei1101/rule-inject/commit/a897c308112ce2265dc61759eeb8f8089e983d05)）。

所感:

- Read の判定は `file.startLine == 1` かつ `file.numLines == file.totalLines` で足りる。`numLines`・`totalLines` は末尾の改行の後ろの空行も数えるが、両方が同じ数え方なので比べられる
- このバージョンでは、既定の行数（2000 行）と長い行の切り詰めは `tool_response` に表れなかった。エージェントへ渡る表示が `tool_response` より短い場合は判定に表れない
- MCP の `tool_response` は構造化された結果（`structuredContent`）を JSON にした文字列で、`str` を返すツールも `{"result": ...}` に包まれる。JSON の中では属性の `"` が `\"` になるため、文字列のまま `<document>` を探さず、JSON として読んでから文字列の値を探す
- 構造化された結果を持たず、テキストだけを返すツールの `tool_response` は確かめていない。JSON として読めない文字列は、そのままテキストとして `<document>` を探す
- 上限を超えた結果では閉じタグの無い `<document>` は出なかったが、インターフェース定義では、閉じタグの無い `<document>` と JSON として読めない結果を既読にしない

### 最小再現コードの要点

フック（`poc/hook_dump.py`）は stdin の JSON をそのまま追記するだけで、検証用のサーバー（`poc/server.py`）は次のように文書を `<document>` で包んで返す。

```python
@mcp.tool()
def small_markdown() -> str:
    """scope=full と scope=summary の文書を 1 つずつ markdown で返す。"""
    return _markdown(
        [
            ("/rules/full.md", "full", _body(0, 3)),
            ("/rules/summary.md", "summary", "説明だけ"),
        ]
    )


@mcp.tool()
def small_json() -> DocList:
    """scope=full と scope=section の項目を json の構造化された結果で返す。"""
    return DocList(
        items=[
            DocItem(path="/rules/full.md", scope="full", body=_body(0, 3)),
            DocItem(path="/rules/section.md", scope="section", body="抜粋"),
        ]
    )
```

`poc/run.sh` が Read の 6 通りのファイルを作り、`--settings`（PostToolUse のフック）・`--mcp-config --strict-mcp-config`（検証用のサーバー）を渡した `claude -p` に 10 件の呼び出しを指示する。
PR #48 の diff の見どころは `poc/run.sh` のプロンプトの 10 件と、`poc/server.py` の大きい結果の 2 つのツール。
